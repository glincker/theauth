Faster hot paths, same answers. New migration `0014-hot-path-indexes` (run it with `theauth db up`, or let `createTheAuth` apply it) adds indexes for agent lookup by token hash, active agents per owner, permissions per agent, delegation links in both directions, the hourly rate limit read and the pending approval list. Without them these lookups scanned their table on SQLite and Postgres (MySQL already indexed the foreign key columns). On a SQLite file with 50,000 agents, 200,000 permissions and 50,000 delegation links, `authorize` through a three hop delegation chain went from about 10 ms to about 0.4 ms. Also: string HMAC secrets are imported once and reused (session cookies, MCP HS256 tokens), device bundle verification and signing reuse imported keys while the JWKS or JWK object is unchanged, the default resource matcher no longer splits strings, the approval hash canonicalizer skips work for plain strings, the delegation liveness walk reads each agent's inbound links once instead of twice, `agent.get` reads the agent and its permissions together, and the admin API pending approvals list reads quorum approvers in one query instead of one per request. Security checks are unchanged and each fast path is pinned to the code it replaced by tests. The measurements, method and noise are in `docs/performance.mdx`.
