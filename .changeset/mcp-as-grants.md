MCP authorization server: new opt-in grants and client compatibility options. `lenientClients` (optionalResource, dropUnknownScopes, loopbackAnyPort, loopbackAllowLocalhost, pathAudience) relaxes strict request checks for real-world clients and is off by default. `clientCredentials` adds the client_credentials grant for confidential clients, mapped to a principal through `resolvePrincipal`, scope-limited, with no refresh token and optional DPoP binding. `tokenExchange` adds RFC 8693 exchange of access tokens issued by this server with scope narrowing, configured-resource audience changes, a nested `act` claim capped at 3 hops, revocation checks and DPoP binding checks. `jwtBearer` redeems RFC 7523 ID-JAG assertions (`typ: oauth-id-jag+jwt`) from trusted issuers with JWKS fetched through the SSRF-safe fetcher, jti replay protection and a subject mapper. Clients can authenticate with `private_key_jwt` (registered `jwks` or `jwks_uri`, or a Client ID Metadata Document). Client ID Metadata Documents honor Cache-Control max-age within 60 seconds to 24 hours and keep a short negative cache for failed fetches. Fixes the step-up `upgrade_url`, which pointed at `/authorize` instead of `/mcp/authorize`. Metadata advertises the enabled grants and `private_key_jwt`. The client_credentials grant, previously rejected, now parses and returns `unsupported_grant_type` unless enabled.
