## What the dashboard does

The KavachOS dashboard provides a visual interface for the operations the SDK handles programmatically: creating and revoking agents, reviewing authorization decisions in the audit log, inspecting delegation chains, managing permissions, and monitoring MCP server registrations. It talks to the KavachOS REST API (served by any framework adapter) and renders everything in a single-page React application.

## Two modes

The dashboard can run in two ways:

1. **Embedded** as a React component (`@kavachos/dashboard`) inside your existing app
2. **Standalone** via the CLI (`npx kavachos dashboard`), which starts its own HTTP server serving the pre-built dashboard

Both modes connect to the same KavachOS REST API and provide identical functionality.

    Import `KavachDashboard` and render it inside a protected admin route in your app. Pass the URL where your KavachOS API is mounted.

          theme="dark"
        />

    ### Backend setup

    The dashboard needs a KavachOS REST API to talk to. Mount any framework adapter to provide it. For example, in a Next.js app:

    ```typescript
    // app/api/kavach/[...kavach]/route.ts
    import { createKavach } from 'kavachos';
    import { kavachNextjs } from '@kavachos/nextjs';

    const kavach = createKavach({
      database: { provider: 'sqlite', url: 'kavach.db' },
    });

    const handlers = kavachNextjs(kavach);

    export const GET = handlers.GET;
    export const POST = handlers.POST;
    export const PATCH = handlers.PATCH;
    export const DELETE = handlers.DELETE;
    ```

    ### Protecting the admin route

    The embedded dashboard does not enforce authentication on its own. Wrap it with your app's auth check:

    ```tsx
    // app/admin/page.tsx
    import { redirect } from 'next/navigation';
    import { getSession } from '@/lib/auth';
    import { KavachDashboard } from '@kavachos/dashboard';

    export default async function AdminPage() {
      const session = await getSession();
      if (!session?.user.isAdmin) redirect('/');

      return <KavachDashboard apiUrl="/api/kavach" theme="dark" />;
    }
    ```

    <Callout type="warn">
      Do not render the dashboard on a public route. It gives full read/write access to all agents, permissions, and audit data.
    </Callout>

  <Tab value="Standalone CLI">
    ### Run with npx

    The CLI starts a standalone HTTP server that serves the pre-built dashboard and proxies API requests to your running KavachOS backend.

    ```bash
    npx kavachos dashboard --port 3100 --api http://localhost:3000
    ```

    This opens the dashboard at `http://localhost:3100`, pointing at a KavachOS API running on port 3000.

    ### CLI flags

    | Flag | Default | Description |
    |---|---|---|
    | `--port` | `3100` | Port for the dashboard server |
    | `--api` | `http://localhost:3000` | URL of your KavachOS REST API |

    ### Setting a dashboard secret

    Set the `KAVACHOS_DASHBOARD_SECRET` environment variable to require authentication:

    ```bash
    KAVACHOS_DASHBOARD_SECRET=my-secret-value npx kavachos dashboard
    ```

    When set, the dashboard shows a login screen and validates the entered secret against the API before granting access. When not set, the dashboard runs in open dev mode with no authentication.

    <Callout type="warn">
      Without `KAVACHOS_DASHBOARD_SECRET`, anyone who can reach the dashboard port has full access. Set this variable in any environment beyond local development.
    </Callout>

## Dashboard pages

The dashboard includes nine pages, accessible from the sidebar navigation.

### Overview

The landing page. Shows active agent count, recent authorization decisions (allowed, denied, rate-limited in the last 24 hours), and user count. Click any stat to navigate to the relevant detail page.

### Agents

Lists all agents across all users. Filter by owner, type (autonomous, delegated, service), and status (active, revoked, expired). From this page you can:

- Create new agents with permissions
- Rotate an agent's token
- Revoke an agent

### Users

Lists all users that own agents. Navigate to a user to see their agents and activity.

### Permissions

View and edit the permission set for any agent. Each row shows the resource pattern, allowed actions, and any active constraints (rate limits, time windows, IP allowlists, argument patterns, approval requirements).

### Delegations

Inspect delegation chains between agents. See which agent delegated what permissions to another, the chain depth, and expiry dates. Revoke delegations from this view.

### Audit

A paginated table of authorization decisions. Filter by agent ID, user ID, time range, action names, and result (allowed, denied, rate_limited). Each row shows the timestamp, agent, action, resource, and outcome. Export filtered results as JSON or CSV.

### MCP servers

Lists registered MCP servers with their endpoints, tools, and auth requirements. View token validation activity for each server.

### Security

Security overview and configuration for the KavachOS instance.

### Settings

Instance-level settings and configuration.

## Dashboard authentication

The standalone CLI server uses a secret-based authentication model:

1. Set `KAVACHOS_DASHBOARD_SECRET` as an environment variable
2. The dashboard shows a login screen on first load
3. The entered value is sent as a `Bearer` token to `/api/dashboard/auth`
4. If it matches the environment variable, the session is stored in `sessionStorage`
5. The session persists until the browser tab is closed or the user clicks "Sign out"

When no secret is configured, the auth endpoint returns `{ ok: true, mode: "dev" }` and the dashboard skips the login screen entirely.

For the embedded React component, the dashboard itself does not handle authentication. You are responsible for protecting the route that renders `KavachDashboard` using your app's existing auth system (session checks, middleware, route guards).

## Customization

### Theming

The dashboard supports `"light"` and `"dark"` themes via the `theme` prop. In dark mode, a `dark` class is applied to the root element:

```tsx
<KavachDashboard apiUrl="/api/kavach" theme="dark" />
```

The dashboard uses Tailwind CSS v4 internally. All styles are scoped to the `[data-kavachos-dashboard]` attribute to avoid conflicts with your app's styles.

### Dependencies

The embedded dashboard (`@kavachos/dashboard`) requires React 19+ as a peer dependency. It bundles its own copies of:

- `@tanstack/react-query` for data fetching and caching
- `lucide-react` for icons
- Tailwind CSS v4 for styling

These are bundled in the package and do not conflict with your app's versions.
