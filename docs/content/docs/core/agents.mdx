## What is an agent identity

`AgentIdentity` is the primary entity in KavachOS. It represents a single AI agent, a process acting on behalf of a human user.

Agents are not users. There are no passwords, sessions, or OAuth flows. An agent has a bearer token and a set of permissions, both managed through the SDK.

## Agent types

<Accordions>
  <Accordion title="autonomous">
    Acts independently without requiring human approval on each call (unless a permission constraint mandates it). The standard type for background agents, cron jobs, and AI assistants that run unattended.
  </Accordion>
  <Accordion title="delegated">
    Receives permissions from another agent through a delegation chain rather than having them assigned at creation. Use this for ephemeral sub-agents spun up to complete a specific task, then discarded.
  </Accordion>
  <Accordion title="service">
    Long-lived identity for infrastructure: an MCP server, an internal microservice, or any process that calls other services on behalf of users. Treat it like a service account.
  </Accordion>
</Accordions>

## Lifecycle

### Creating an agent

```typescript
const agent = await kavach.agent.create({
  ownerId: 'user-123',
  name: 'github-reader',
  type: 'autonomous',
  permissions: [
    { resource: 'mcp:github:*', actions: ['read'] },
  ],
  expiresAt: new Date(Date.now() + 7 * 24 * 3_600_000), // 7 days
  metadata: { purpose: 'nightly PR review' },
});

console.log(agent.token); // kv_a3f8c2e1...
```

<Callout type="warn">
  The token is returned **once** at creation. KavachOS stores only the SHA-256 hash, so the plaintext cannot be recovered later. Save it immediately or call `rotate()` to get a new one.
</Callout>

### Tokens

Tokens use the `kv_` prefix followed by 32 cryptographically random bytes encoded as base64url:

```
kv_a3f8c2e1d4b5...
```

Authenticate by passing the token as a Bearer credential:

```http
Authorization: Bearer kv_a3f8c2e1d4b5...
```

KavachOS stores only the SHA-256 hash of each token. A full database dump does not reveal active tokens. The only thing an attacker could find is the `tokenPrefix` (the first 8 characters after `kv_`), which is stored for identification in logs and the admin dashboard.

### Token rotation

Rotation issues a new token and immediately invalidates the old one. The operation is atomic: there is no window where both tokens are valid.

```typescript
const rotated = await kavach.agent.rotate(agentId);
// rotated.token is the new plaintext token
// The previous token is rejected on all subsequent calls
```

Rotate tokens on a schedule, or whenever you suspect a token has been exposed.

### Token-based authorization

When a caller only has a raw bearer token (for example, in HTTP middleware), use `authorizeByToken` instead of `authorize`:

```typescript
const token = request.headers.get('Authorization')?.replace('Bearer ', '');
if (!token) return new Response('Unauthorized', { status: 401 });

const result = await kavach.authorizeByToken(token, {
  action: 'read',
  resource: 'mcp:github:repos',
});

if (!result.allowed) {
  return new Response(result.reason ?? 'Forbidden', { status: 403 });
}
```

This performs a single database lookup (hash comparison), then evaluates permissions in memory. No JWTs, no network calls.

### Listing and filtering agents

```typescript
// All agents owned by a user
const agents = await kavach.agent.list({ userId: 'user-123' });

// Only active autonomous agents
const active = await kavach.agent.list({
  userId: 'user-123',
  status: 'active',
  type: 'autonomous',
});
```

The `AgentFilter` accepts three optional fields:

| Field | Type | Description |
|---|---|---|
| `userId` | `string` | Filter by owner |
| `status` | `'active' \| 'revoked' \| 'expired'` | Filter by current status |
| `type` | `'autonomous' \| 'delegated' \| 'service'` | Filter by agent type |

### Updating an agent

```typescript
const updated = await kavach.agent.update(agentId, {
  name: 'github-reader-v2',
  permissions: [
    { resource: 'mcp:github:*', actions: ['read', 'comment'] },
  ],
  metadata: { version: 2 },
});
```

All fields in the update input are optional. When `permissions` is provided, the entire permission set is replaced (not merged). Permission changes take effect on the next `authorize()` call.

### Revoking an agent

```typescript
await kavach.agent.revoke(agentId);
// All future authorize() or authorizeByToken() calls return allowed: false
// The agent's token is also invalidated immediately
```

<Callout type="error">
  Revocation is permanent. There is no un-revoke. To restore access, create a new agent.
</Callout>

## Agent limits

The default limit is **10** active agents per user. You can change it at initialization:

```typescript
const kavach = await createKavach({
  database: { provider: 'sqlite', url: 'kavach.db' },
  agents: {
    maxPerUser: 50,
    tokenExpiry: '7d', // default token lifetime
  },
});
```

`tokenExpiry` accepts duration strings like `"24h"`, `"7d"`, `"30m"`, or `"3600s"`. This sets the default `expiresAt` for agents created without an explicit expiry.

When a user already has the maximum number of active agents, `kavach.agent.create()` throws an error. Revoked and expired agents do not count toward the limit.
