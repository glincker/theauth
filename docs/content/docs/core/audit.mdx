## How audit logging works

Every call to `kavach.authorize()` or `kavach.authorizeByToken()` writes an entry to the audit log, regardless of outcome. Allowed, denied, and rate-limited calls are all recorded. The log is append-only: entries are never modified after insertion.

Each authorization result includes an `auditId` linking the decision to its log entry:

```typescript
const result = await kavach.authorize(agent.id, {
  action: 'read',
  resource: 'mcp:github:repos',
});

console.log(result.auditId); // UUID of the audit log entry
```

Audit logging is enabled by default. You can disable it by setting `auditAll: false` in the agent configuration, but this is not recommended for production.

## Querying logs

All filter fields are optional and can be combined. Without filters, the query returns all entries up to the `limit`.

```typescript
const logs = await kavach.audit.query({
  agentId: 'agt_...',
  userId: 'user-123',
  result: 'denied',
  since: new Date('2025-01-01'),
  until: new Date('2025-02-01'),
  actions: ['write', 'delete'],
  limit: 100,
  offset: 0,
});
```

## Exporting logs

Export audit entries as JSON or CSV for compliance tools, spreadsheets, or external SIEM systems.

```typescript
// JSON export
const json = await kavach.audit.export({ format: 'json' });

// CSV export
const csv = await kavach.audit.export({ format: 'csv' });

// Export a specific time range
const q4 = await kavach.audit.export({
  format: 'csv',
  since: new Date('2024-10-01'),
  until: new Date('2025-01-01'),
});
```

The CSV output includes a header row: `id,agentId,userId,action,resource,result,reason,durationMs,tokensCost,timestamp`. Each row is one authorization decision.

Exports are capped at 10,000 entries. For larger datasets, use `kavach.audit.query()` with pagination and build the export yourself.

<Callout type="info">
  Both `since` and `until` are optional on exports. Omitting both exports the entire log (up to the 10,000 cap).
</Callout>

## Cost tracking

When you pass `tokensCost` in the authorization context, the value is recorded in the audit log. Use `getCostSummary()` to aggregate costs across agents and time periods.

```typescript
const result = await kavach.authorize(agent.id, {
  action: 'execute',
  resource: 'mcp:openai:chat',
}, {
  tokensCost: 1542,
});

// Later, aggregate costs
const summary = await kavach.audit.getCostSummary({
  userId: 'user-123',
  since: new Date('2025-03-01'),
  until: new Date('2025-04-01'),
});

console.log(summary.totalCost);   // total tokens across all agents
console.log(summary.byAgent);     // [{ agentId, totalCost, callCount }, ...]
console.log(summary.byDay);       // [{ date: '2025-03-15', totalCost, callCount }, ...]
```

## Retention cleanup

For long-running deployments, periodically remove old entries to keep the table size manageable. `cleanup()` deletes all entries older than the specified retention period and returns the count of deleted rows.

```typescript
const { deleted } = await kavach.audit.cleanup({ retentionDays: 90 });
console.log(`Removed ${deleted} entries older than 90 days`);
```

<Callout type="warn">
  Cleanup permanently deletes entries. If you need to keep records for compliance, export them before running cleanup.
</Callout>

## Compliance references

The audit trail is designed to satisfy record-keeping requirements in several compliance frameworks.

<Accordions>
  <Accordion title="EU AI Act, Article 12">
    Article 12 requires high-risk AI systems to log events automatically throughout the system lifecycle, including the period of activity and data used. KavachOS records every authorization decision with agent identity, resource, action, parameters, outcome, and timestamp.
  </Accordion>
  <Accordion title="NIST AI RMF (GOVERN 1.7 / MANAGE 4.2)">
    The NIST AI Risk Management Framework calls for documented accountability mechanisms and the ability to trace AI actions to specific identities. The append-only audit trail links every decision to a named agent and its owning user.
  </Accordion>
  <Accordion title="SOC 2 (CC6.1 through CC7.2)">
    SOC 2 trust services criteria for logical access controls and system monitoring require evidence that access is granted only to authorized identities and that access events are logged. The `allowed`/`denied`/`rate_limited` result field satisfies CC6.1 through CC6.3. The append-only structure satisfies CC7.2.
  </Accordion>
  <Accordion title="ISO 42001, Annex A.8">
    ISO 42001 recommends documenting the behavior of AI systems in production. Exporting the audit log as JSON or CSV provides auditors a machine-readable record of every decision the system made.
  </Accordion>
</Accordions>

## Usage patterns

### Monthly access report for a user

```typescript
const entries = await kavach.audit.query({
  userId: 'user-123',
  since: new Date('2025-03-01'),
  until: new Date('2025-04-01'),
});
```

### Finding agents with repeated denials

```typescript
const denied = await kavach.audit.query({
  result: 'denied',
  since: new Date(new Date().setHours(0, 0, 0, 0)),
});

const countsByAgent = denied.reduce<Record<string, number>>((acc, entry) => {
  acc[entry.agentId] = (acc[entry.agentId] ?? 0) + 1;
  return acc;
}, {});
```

### Detecting high-frequency agents

```typescript
const recentCalls = await kavach.audit.query({
  agentId: agent.id,
  since: new Date(Date.now() - 3_600_000), // last hour
});

if (recentCalls.length > 500) {
  await kavach.agent.revoke(agent.id);
}
```

<Callout type="warn">
  A sudden spike in call volume from a single agent often indicates a runaway loop. Use `kavach.agent.revoke()` to suspend the agent while you investigate.
</Callout>
