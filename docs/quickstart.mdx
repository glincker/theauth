Want a full app instead? `pnpm create @glinr/theauth-app` scaffolds a Next.js SaaS, a Hono MCP server or a Cloudflare Worker with theAuth wired up (also `npm create`, `yarn create`, `bun create`). The CLI asks for a directory, a template, a package manager and a database driver. It writes a `.env` with generated secrets and adds a `doctor` script. The generated code creates the owner with `theauth.user.create` and stores data in a SQLite file. The Hono MCP template still keeps MCP clients, codes and tokens in memory, because database backed MCP stores are not available yet.

## Fastest start: theauth init

In an existing project, `theauth init` writes a working server, creates the owner user and a demo agent, and prints the next steps. It reads `package.json` to pick the framework (Hono, Express, Fastify, Next.js, SvelteKit or Nuxt) and the package manager, and it stores data in a SQLite file so it survives restarts.

```bash title="terminal"
npx theauth init --yes
```

```text title="output"
TheAuth init
Framework: hono, database: sqlite

created     src/theauth.ts
created     src/seed.ts
created     src/server.ts
created     .env.example
created     .gitignore
created     .env (generated secrets, gitignored)

Note: Detected hono from package.json.

Next steps

  1. Install dependencies:
       npm install @glinr/theauth @glinr/theauth-hono better-sqlite3 hono @hono/node-server zod
       npm install -D tsx
  2. Start the server (it creates the owner user and a demo agent on boot):
       npx tsx --env-file=.env src/server.ts
  3. List agents through the mounted routes:
       curl -s -H "Authorization: Bearer $(grep '^ADMIN_API_KEY=' .env | cut -d= -f2)" http://localhost:3000/api/theauth/agents
  4. Check the setup, including the running server:
       theauth doctor --live http://localhost:3000/api/theauth

Docs: https://theauth.dev/docs
```

After you install and start the server:

```text title="server log"
Owner user: owner@example.com (50005a21-0612-4ca0-a085-0c6f0ea04706)
Demo agent created: 72bab466-1fc7-41ad-93f9-502e02b56c23
Agent token (shown once, store it safely): ta_x8tSbjRs7NnH21WA1_-yGKZRqmucw7a_u4Yo0wkhKjU
Listening on http://localhost:3000
```

The curl from step 3 returns the demo agent:

```json title="response"
{"data":[{"id":"72bab466-1fc7-41ad-93f9-502e02b56c23","ownerId":"50005a21-0612-4ca0-a085-0c6f0ea04706","name":"demo-agent","type":"autonomous","token":"","permissions":[{"resource":"documents","actions":["read","write"]}],"status":"active", ...}]}
```

The same call without the `Authorization` header answers 401. The seed creates the owner with `theauth.user.create` before the agent, so the foreign key on `owner_id` holds. Running `init` again skips every file that exists, so it never overwrites your edits (pass `--force` to replace the generated files; `.env` is only ever created). See [CLI tools](/cli-tools#init) for every flag. The two tracks below show the same calls by hand.

## Track A: add agent auth

<Steps>

<Step>

### Install

```bash title="terminal"
pnpm add @glinr/theauth better-sqlite3
```

`npm install` and `yarn add` work the same way. The Node SQLite driver is `better-sqlite3`; on Bun, Deno and Workers use the matching [database provider](/database).

The unscoped `theauth` package is an alias for `@glinr/theauth-cli`, so `npx theauth init` sets up agent identity and MCP OAuth 2.1 without a separate CLI install. To keep the command on your PATH, install it globally with `npm install -g theauth`.

</Step>

<Step>

### Create an instance and an owner

Every agent has an owner: a user ID that exists as a row in `theauth_users` (the `owner_id` column is a foreign key, so creating an agent for an unknown ID fails). Human auth in the next track creates these rows for you; if you already have users in another system, call `theauth.user.create()` for each one you want to own agents. It validates and lowercases the email, and returns the existing row if the email is already registered.

```ts title="agent.ts"
import { createTheAuth } from '@glinr/theauth';

const theauth = await createTheAuth({
  database: { provider: 'sqlite-native', url: './theauth.db' }, // a file on disk, kept across runs
  agents: { enabled: true, maxPerUser: 10, auditAll: true, tokenExpiry: '24h' },
});

// Owner row. Skip this if the user came from the human auth track.
const owner = await theauth.user.create({
  id: 'user-123', // optional, generated when omitted
  email: 'owner@example.com',
  name: 'Owner',
});
```

</Step>

<Step>

### Create an agent

```ts title="agent.ts"
const agent = await theauth.agent.create({
  ownerId: 'user-123',
  name: 'github-reader',
  type: 'autonomous',
  permissions: [
    { resource: 'mcp:github:*', actions: ['read'] },
    {
      resource: 'mcp:deploy:production',
      actions: ['execute'],
      constraints: {
        requireApproval: true,   // authorize() denies until approval is wired up
        maxCallsPerHour: 5,
      },
    },
  ],
});

// agent.token is the bearer token. Agent tokens start with "ta_".
console.log(agent.token);
```

<Warning>
The token is shown once, at creation. Store it in your secrets manager or hand it straight to the agent. It cannot be recovered, only rotated.
</Warning>

New agent tokens start with `ta_`. Tokens issued by earlier versions start with `kv_` (the old Kavach name) and keep working until you rotate them (see [RENAME-MAP.md](https://github.com/glincker/theauth/blob/main/RENAME-MAP.md)).

There are three agent types:

| Type | When to use |
|---|---|
| `autonomous` | Runs without human involvement. Default for most agents. |
| `delegated` | Receives permissions from another agent via a delegation chain. |
| `service` | Long-lived service account identity. |

</Step>

<Step>

### Authorize an action and read the audit trail

`authorize` returns `{ allowed, reason?, auditId }`. `reason` explains a denial. Budget policies are not checked here; call `theauth.policies.checkBudget()` yourself if you use them.

```ts title="agent.ts"
const result = await theauth.authorize(agent.id, {
  action: 'read',
  resource: 'mcp:github:repos',
});
if (!result.allowed) throw new Error(`Denied: ${result.reason}`);

// With only the raw bearer token (from an incoming HTTP request):
const byToken = await theauth.authorizeByToken(agent.token, {
  action: 'read',
  resource: 'mcp:github:repos',
});

// Every decision is logged while auditAll is on (the default).
const logs = await theauth.audit.query({ agentId: agent.id });
const denied = await theauth.audit.query({ agentId: agent.id, result: 'denied' });
const csv = await theauth.audit.export({ format: 'csv' });
```

Run it with `npx tsx agent.ts`.

</Step>

</Steps>

## Track B: add human auth

theAuth ships 14 human auth methods and 48 OAuth providers as plugins and modules; this track uses email and password, the most common starting point. See [Authentication](/auth) for the rest.

<Steps>

<Step>

### Install

```bash title="terminal"
pnpm add @glinr/theauth better-sqlite3
```

</Step>

<Step>

### Turn on email and password

`emailPassword` is part of core. It serves `POST /auth/email/sign-up`, `/auth/email/sign-in`, `/auth/email/verify`, `/auth/email/resend-verification`, `/auth/email/forgot-password`, `/auth/email/reset-password` and `/auth/email/change-password` from the same handler as everything else. You supply the email transport; the callbacks below just log. Passwords are hashed before storage, and sessions are the same sessions the rest of theAuth reads.

```ts title="human.ts"
import { createTheAuth } from '@glinr/theauth';
import { createTheAuthHandler } from '@glinr/theauth/http';

const verifications: string[] = [];

const theauth = await createTheAuth({
  database: { provider: 'sqlite', url: ':memory:' },
  auth: { session: { secret: 'a-session-secret-of-at-least-32-characters' } },
  agents: { enabled: true, maxPerUser: 10, auditAll: true }, // for the agent step below
  emailVerification: {
    verifyUrl: 'http://localhost:3000/verify-email',
    sendVerificationEmail: async (email, token, url) => {
      verifications.push(token);
      console.log('verify', email, url);
    },
  },
  emailPassword: {}, // requireVerification is true unless you set it to false
});

const handler = createTheAuthHandler(theauth, { basePath: '/api/theauth' });
```

</Step>

<Step>

### Sign up, verify and sign in

The handler takes standard `Request` objects, so you can call it directly or mount it with a [framework adapter](/adapters).

```ts title="human.ts"
const post = (path: string, body: unknown) =>
  handler(
    new Request(`http://localhost/api/theauth${path}`, {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify(body),
    }),
  );

const creds = { email: 'ada@example.com', password: 'correct horse battery' };

console.log((await post('/auth/email/sign-up', { ...creds, name: 'Ada' })).status); // 201, no session yet
console.log((await post('/auth/email/sign-in', creds)).status); // 403 EMAIL_NOT_VERIFIED
await post('/auth/email/verify', { token: verifications[0] });

const signIn = await post('/auth/email/sign-in', creds);
const { user, session } = await signIn.json(); // { user, session: { token, expiresAt } }

const me = await handler(
  new Request('http://localhost/api/theauth/auth/session', {
    headers: { authorization: `Bearer ${session.token}` },
  }),
);
console.log((await me.json()).user.email); // ada@example.com
```

Run it with `npx tsx human.ts`. The browser clients take `emailPassword: true` and call the same routes ([React](/react), [Vue](/vue), [Svelte](/svelte), [Expo](/expo), [Electron](/electron)). Details, the error codes and what the routes reveal are on [Email and password](/auth/email-password).

</Step>

<Step>

### Give the user an agent

The sign-in response contains `user.id`. Pass it as `ownerId` in Track A and the foreign key is satisfied with no manual seeding.

```ts title="human.ts"
const agent = await theauth.agent.create({
  ownerId: user.id,
  name: 'assistant',
  type: 'autonomous',
  permissions: [{ resource: 'mcp:github:*', actions: ['read'] }],
});
```

</Step>

</Steps>

Prefer to keep Clerk, Auth.js, better-auth or your own login? Skip Track B and pass your user ID as `ownerId`, or wrap your resolver with `customAuth` ([details](/auth/email-password)).

## Delegation

An orchestrator agent can delegate a subset of its permissions to a sub-agent. The delegation has its own expiry and a `maxDepth` (default 3) to prevent unbounded chains: the new link's depth must be less than or equal to `maxDepth`.

```ts
const sub = await theauth.agent.create({
  ownerId: 'user-123',
  name: 'sub-reader',
  type: 'delegated',
  permissions: [],  // starts empty; receives permissions via delegation
});

await theauth.delegate({
  fromAgent: agent.id,
  toAgent: sub.id,
  permissions: [{ resource: 'mcp:github:issues', actions: ['read'] }],
  expiresAt: new Date(Date.now() + 3_600_000),  // 1 hour
  maxDepth: 2,
});

// Permissions this agent currently holds through active delegations
const perms = await theauth.delegation.getEffectivePermissions(sub.id);
```

<Info>
An agent cannot delegate permissions it does not hold itself. Attempts to escalate are rejected at the point of delegation, not at authorization time.
</Info>

## Full working example

<Expandable title="Self-contained script: create, authorize, rotate, delegate, export">

Covers agent creation, authorization by ID and token, token rotation, delegation, and audit export.

```ts
import { createTheAuth } from '@glinr/theauth';

const theauth = await createTheAuth({
  database: { provider: 'sqlite', url: ':memory:' },
  agents: { enabled: true, maxPerUser: 10, auditAll: true, tokenExpiry: '24h' },
});

// The owner must exist in theauth_users (see Track A, step 2)
await theauth.user.create({ id: 'user-123', email: 'owner@example.com', name: 'Owner' });

// Create an agent with wildcard read on github resources
const agent = await theauth.agent.create({
  ownerId: 'user-123',
  name: 'github-reader',
  type: 'autonomous',
  permissions: [
    { resource: 'mcp:github:*', actions: ['read'] },
    { resource: 'mcp:github:issues', actions: ['read', 'comment'] },
  ],
});

// Allowed: mcp:github:repos matches mcp:github:*
const r1 = await theauth.authorize(agent.id, {
  action: 'read',
  resource: 'mcp:github:repos',
});
console.log(r1.allowed);  // true

// Denied: no write permission
const r2 = await theauth.authorize(agent.id, {
  action: 'write',
  resource: 'mcp:github:repos',
});
console.log(r2.allowed);  // false

// Authorize using the raw bearer token
const r3 = await theauth.authorizeByToken(agent.token, {
  action: 'read',
  resource: 'mcp:github:issues',
});
console.log(r3.allowed);  // true

// Rotate: old token is immediately invalid
const rotated = await theauth.agent.rotate(agent.id);
console.log(rotated.token);  // new ta_... token

// Delegate a subset to a sub-agent
const sub = await theauth.agent.create({
  ownerId: 'user-123',
  name: 'sub-reader',
  type: 'delegated',
  permissions: [],
});

await theauth.delegate({
  fromAgent: agent.id,
  toAgent: sub.id,
  permissions: [{ resource: 'mcp:github:issues', actions: ['read'] }],
  expiresAt: new Date(Date.now() + 3_600_000),
  maxDepth: 2,
});

const perms = await theauth.delegation.getEffectivePermissions(sub.id);
console.log(perms);
// [{ resource: 'mcp:github:issues', actions: ['read'] }]  (delegated permissions only)

// Export the audit trail (up to the 10,000 most recent entries)
const csv = await theauth.audit.export({ format: 'csv' });
```

</Expandable>

## Cloudflare Workers

theAuth runs on Workers with no changes. Pass a D1 binding as the database and use the Hono adapter.

```typescript
import { createTheAuth } from '@glinr/theauth';
import { Hono } from 'hono';

type Env = { THEAUTH_DB: D1Database };

const app = new Hono<{ Bindings: Env }>();

app.get('/health', async (c) => {
  const theauth = await createTheAuth({
    database: { provider: 'd1', binding: c.env.THEAUTH_DB },
    agents: { enabled: true },
  });

  const agent = await theauth.agent.create({
    ownerId: 'user-1',
    name: 'my-agent',
    type: 'autonomous',
    permissions: [{ resource: 'mcp:github:*', actions: ['read'] }],
  });

  return c.json({ agent });
});

export default app;
```

Bind a D1 database in your `wrangler.toml`:

```toml
[[d1_databases]]
binding = "THEAUTH_DB"
database_name = "theauth"
database_id = "<your-database-id>"
```

Run `npx wrangler d1 execute theauth --file=./theauth-schema.sql` to apply the schema yourself (and set `skipMigrations: true` inside `database`), or leave it at its default of `false` and theAuth creates the tables with `CREATE TABLE IF NOT EXISTS` on startup.

<Info>
`createTheAuth` is always async, not only with D1. Workers and Deno both support top-level await, so you can also initialize outside the handler if you use a module worker.
</Info>

## Troubleshooting

### "Email address has not been verified" after sign-up

With the `emailPassword` config, sign-in requires email verification by default and fails with `EMAIL_NOT_VERIFIED` (HTTP 403). Either:
1. Post the token from the verification email (the one passed to your `sendVerificationEmail` callback) to `/auth/email/verify`
2. Set `requireVerification: false` in the `emailPassword` config (development only)

### "FOREIGN KEY constraint failed" when creating agents

The `ownerId` must match a row in `theauth_users`. Sign the user up with `emailPassword` (Track B), or create one with `theauth.user.create()` as shown in step 2 of Track A.

### Session not persisting after page reload

The React hooks store sessions in `localStorage`. Make sure your app is wrapped in `<TheAuthProvider>`. If using SSR (Next.js), wrap the provider in a `"use client"` component.
