<Columns cols={2}>
<div>
An `AgentIdentity` is the primary entity in theAuth. It represents one AI agent, a process acting on behalf of a human user. Agents are not users. No password, no session, no OAuth flow. Just a token, a set of permissions, and an audit row for every call.

Create one against an existing user ID, hand the token to the agent, and check every action through `authorize()`.
</div>

```ts
const agent = await theauth.agent.create({
  ownerId: user.id,
  name: 'code-reviewer',
  type: 'autonomous',
  permissions: [
    { resource: 'mcp:github:*', actions: ['read'] },
  ],
});

// agent.token is a kv_... bearer, shown once, hashed at rest
console.log(agent.token);
```
</Columns>

## Anatomy

<ParamField path="id" type="string">Stable identifier (a UUID). Never changes.</ParamField>
<ParamField path="token" type="string">Bearer token with a `kv_` prefix. Shown once at creation, then SHA-256 hashed. Rotate to replace.</ParamField>
<ParamField path="permissions" type="Permission[]">What this agent is allowed to do. Evaluated at every `authorize()` call.</ParamField>
<ParamField path="status" type="'active' | 'revoked' | 'expired'">Current state. Revocation is permanent.</ParamField>
<ParamField path="ownerId" type="string">The user who owns this agent. Must match an existing row in `theauth_users` (foreign key).</ParamField>
<ParamField path="name" type="string">Human-readable label.</ParamField>
<ParamField path="type" type="'autonomous' | 'delegated' | 'service'">Determines how the agent acquires and uses permissions.</ParamField>
<ParamField path="expiresAt" type="Date" default="now + agents.tokenExpiry (24h)">Optional at creation; when omitted it defaults to `agents.tokenExpiry` from now. Token validation (`authorizeByToken`) rejects an expired agent and flips its `status` to `expired`. `authorize(agentId)` only checks `status`, so it does not notice an elapsed `expiresAt` until the agent has been marked expired.</ParamField>
<ParamField path="metadata" type="Record<string, unknown>" default="{}">Arbitrary key/value pairs for your own use.</ParamField>

## Agent types

<AccordionGroup>
  <Accordion title="autonomous" icon="robot">
    Acts independently without requiring human approval on each call, unless a permission constraint mandates it. The standard type for background agents, cron jobs, and AI assistants that run unattended.
  </Accordion>
  <Accordion title="delegated" icon="link">
    Receives permissions from another agent via a delegation chain rather than having them declared at creation. Use this for ephemeral sub-agents spun up to complete one task, then discarded.
  </Accordion>
  <Accordion title="service" icon="server">
    Long-lived identity for infrastructure, such as an MCP server or an internal microservice that calls other services on behalf of users. Treat it like a service account.
  </Accordion>
</AccordionGroup>

## Lifecycle

<Steps>

<Step title="Create">

```ts
const agent = await theauth.agent.create({
  ownerId: 'user-123',
  name: 'github-reader',
  type: 'autonomous',
  permissions: [
    { resource: 'mcp:github:*', actions: ['read'] },
  ],
  expiresAt: new Date(Date.now() + 7 * 24 * 3_600_000), // optional, defaults to 24h from now
  metadata: { purpose: 'nightly PR review' },
});

console.log(agent.token); // kv_..., only shown here
```

<Warning>
The token is returned once at creation. theAuth stores only the SHA-256 hash, so the plaintext cannot be recovered later. Save it immediately or rotate to get a new one.
</Warning>

</Step>

<Step title="Authenticate">

Tokens use the `kv_` prefix followed by 32 random bytes encoded as base64url (43 characters, 46 in total). Pass as a Bearer credential:

```http
Authorization: Bearer kv_a3f8c2e1d4b5...
```

<Tip>
Hash-only storage: a full database dump cannot reveal an active token. There are no secrets to rotate after a DB breach, only the tokens themselves.
</Tip>

</Step>

<Step title="Authorize">

When a caller only has the raw token, use `authorizeByToken` in your HTTP middleware:

```ts
const token = request.headers.get('Authorization')?.replace('Bearer ', '');
if (!token) return new Response('Unauthorized', { status: 401 });

const result = await theauth.authorizeByToken(token, {
  action: 'read',
  resource: 'mcp:github:repos',
});

if (!result.allowed) {
  return new Response(result.reason ?? 'Forbidden', { status: 403 });
}
```

The token is hashed and looked up in the database, then permissions are evaluated and the decision is written to the audit log. No JWTs, no network round-trip. This path checks the agent's own permissions only; permissions it holds through delegation are applied by `authorize(agentId, ...)`.

<Frame caption="An authorize() call checks permissions, writes the audit record and returns allowed with an auditId.">
  <img src="/images/diagrams/authorize-flow.png" alt="Isometric diagram of an agent request passes the theAuth gate, which checks permissions and writes an audit record, before reaching your MCP server or API. The result is allowed: true with an audit id." />
</Frame>

</Step>

<Step title="Rotate">

Rotation issues a new token and immediately invalidates the old one. It is a single update, so there is no window where both are valid. Only active agents can be rotated.

```ts
const rotated = await theauth.agent.rotate(agentId);
// rotated.token is the new plaintext token
```

Rotate on a schedule, or any time you suspect a token has been exposed.

</Step>

<Step title="Update or list">

Permission updates take effect immediately. In-flight requests that already passed authorization are not affected.

```ts
await theauth.agent.update(agentId, {
  name: 'github-reader-v2',
  permissions: [{ resource: 'mcp:github:*', actions: ['read', 'comment'] }],
});

const active = await theauth.agent.list({
  userId: 'user-123',
  status: 'active',
  type: 'autonomous',
});
```

</Step>

<Step title="Revoke">

```ts
await theauth.agent.revoke(agentId);
// All future authorize() calls return allowed: false
// The agent's token is rejected immediately
```

Each attempt by a revoked or expired agent is still written to the audit log as a denied row with the reason `agent_revoked` or `agent_expired`. See [what gets recorded](/audit-trail#what-gets-recorded).

<Warning>
Revocation is permanent. There is no un-revoke. To restore access, create a new agent.
</Warning>

</Step>

</Steps>

## Limits

The default is 10 active agents per user. Raise at initialization:

```ts
const theauth = await createTheAuth({
  database: { provider: 'sqlite', url: 'theauth.db' },
  agents: {
    enabled: true,
    maxPerUser: 50,
  },
});
```

The cap counts active agents. Creating one past it throws a plain `Error` with the message `User <id> has reached the maximum of <n> active agents.` (there is no dedicated error code, and the REST endpoint reports it as `500 INTERNAL_ERROR`).

## What agents aren't

<Info>
An agent is not a user. It has no email, no password, no session, no OAuth account. It has a bearer token and a permission set. If you find yourself reaching for password reset, email verification, or social sign-in on an agent, you want a user, not an agent. Create the user first, then create agents that the user owns.
</Info>
