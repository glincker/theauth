## Setup

<Steps>
<Step>
### Get credentials

In your Vercel team, open **Settings**, then **Apps**, and click **Create**. Under **Authorization Callback URLs**, add your redirect URI, then generate a client secret and enable the `openid`, `email` and `profile` permissions:

```
https://your-app.com/api/theauth/auth/oauth/callback/vercel
```
</Step>

<Step>
### Configure

```ts title="lib/theauth.ts"
import { createTheAuth } from '@glinr/theauth';
import { oauth, createVercelProvider } from '@glinr/theauth/auth';

const theauth = await createTheAuth({
  database: { provider: 'sqlite', url: 'theauth.db' },
  secret: process.env.THEAUTH_SECRET!,
  baseUrl: 'https://your-app.com/api/theauth',
  auth: { session: { secret: process.env.THEAUTH_SECRET! } },
  plugins: [
    oauth({
      providers: {
        vercel: createVercelProvider({
          clientId: process.env.VERCEL_CLIENT_ID!,
          clientSecret: process.env.VERCEL_CLIENT_SECRET!,
        }),
      },
    }),
  ],
});
```

```bash
VERCEL_CLIENT_ID=...
VERCEL_CLIENT_SECRET=...
```
</Step>
</Steps>

## Scopes

Default scopes: `openid`, `email`, `profile`

| Scope | What it unlocks |
|-------|----------------|
| `openid` | OIDC identity |
| `email` | Email address |
| `profile` | Name and profile picture |
| `offline_access` | A refresh token (needed for `getAccessToken` refreshes) |

Scopes the app does not have enabled in its dashboard settings are dropped by Vercel.

## How it works

- This uses the Sign in with Vercel authorization server: `https://vercel.com/oauth/authorize`, `https://api.vercel.com/login/oauth/token` and `https://api.vercel.com/login/oauth/userinfo`.
- PKCE with S256 is required and always sent. Client credentials go in the form body.
- The userinfo call is a POST with the access token as a Bearer header. It returns `sub`, `email`, `email_verified`, `name`, `preferred_username` and `picture`. The email counts as verified only when `email_verified` is true.
- Add `offline_access` to `scopes` to receive a refresh token.

<Info>
  `vercelProvider` (the older preset) targets Vercel's marketplace integration endpoints and cannot read the profile. It is still exported for existing code. Use `createVercelProvider` for new setups.
</Info>

Vendor docs: [Sign in with Vercel authorization server API](https://vercel.com/docs/sign-in-with-vercel/authorization-server-api).

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/auth/oauth/authorize/vercel` | Redirect to Vercel |
| GET | `/auth/oauth/callback/vercel` | Handle callback |
