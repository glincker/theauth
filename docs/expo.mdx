`@glinr/theauth-expo` brings theAuth auth to React Native and Expo apps. It stores session tokens in any storage adapter you choose. AsyncStorage, SecureStore, or your own, and sends them via `Authorization` header rather than cookies.

## Installation

```bash
npm install @glinr/theauth-expo
# or
pnpm add @glinr/theauth-expo
```

You also need a storage library. The most common choices:

```bash
npx expo install @react-native-async-storage/async-storage
# or for encrypted storage
npx expo install expo-secure-store
```

## Setup

<Steps>
<Step>
### Wrap your app

```tsx
// app/_layout.tsx (Expo Router) or App.tsx
import { TheAuthExpoProvider } from '@glinr/theauth-expo';
import AsyncStorage from '@react-native-async-storage/async-storage';

export default function RootLayout() {
  return (
    <TheAuthExpoProvider
      config={{
        basePath: 'https://api.myapp.com/api/theauth',
        storage: AsyncStorage,
      }}
    >
      <Stack />
    </TheAuthExpoProvider>
  );
}
```

The `storage` prop accepts any object with `getItem`, `setItem`, and `removeItem` methods, the same interface as `AsyncStorage` and `expo-secure-store`.
</Step>

<Step>
### Use the hooks

```tsx
import { useSignIn, useUser } from '@glinr/theauth-expo';

export function LoginScreen() {
  const { signIn, isLoading, error } = useSignIn();

  async function handleLogin() {
    const result = await signIn('user@example.com', 'password');
    if (result.success) {
      router.replace('/home');
    }
  }

  return (
    <View>
      <Button onPress={handleLogin} disabled={isLoading} title="Sign in" />
      {error && <Text>{error}</Text>}
    </View>
  );
}
```
</Step>
</Steps>

## Secure token storage

For production apps, use `expo-secure-store` to keep the session token in the Keychain (iOS) or Keystore (Android):

```tsx
import * as SecureStore from 'expo-secure-store';
import { TheAuthExpoProvider, createSecureStoreStorage } from '@glinr/theauth-expo';

<TheAuthExpoProvider
  config={{ basePath: 'https://api.myapp.com/api/theauth', storage: createSecureStoreStorage(SecureStore) }}
>
  {children}
</TheAuthExpoProvider>
```

## Social sign-in

The app opens the provider in the system browser, and the server sends the browser back to your app with a single-use code. The app trades that code, together with a PKCE verifier that never left the device, for a session. The session token is never placed in a URL.

<Steps>
<Step title="Allow your app's redirect URI on the server">
```typescript
oauth({
  providers: { github: github({ clientId, clientSecret }) },
  mobile: { redirectUris: ['myapp://auth/callback'] },
})
```
Matching is exact. Without `mobile`, the mobile flow is off.
</Step>
<Step title="Configure the provider in the app">
```tsx
import * as WebBrowser from 'expo-web-browser';
import * as Crypto from 'expo-crypto';
import * as Linking from 'expo-linking';
import { AppState } from 'react-native';

const config = {
  basePath: 'https://api.myapp.com/api/theauth',
  storage: createSecureStoreStorage(SecureStore),
  appState: AppState,
  social: {
    redirectUri: Linking.createURL('auth/callback'),
    openAuthSession: (url, redirectUri) => WebBrowser.openAuthSessionAsync(url, redirectUri),
    randomBytes: (n) => Crypto.getRandomBytesAsync(n),
    sha256: async (input) =>
      new Uint8Array(
        await Crypto.digest(Crypto.CryptoDigestAlgorithm.SHA256, new TextEncoder().encode(input)),
      ),
  },
};
```
</Step>
<Step title="Call the hook">
```tsx
import { useSocialSignIn } from '@glinr/theauth-expo';

const { signInWithProvider, isLoading, error } = useSocialSignIn();
<Button title="Continue with GitHub" onPress={() => signInWithProvider('github')} />
```
</Step>
</Steps>

If the user has a required second factor, `signInWithProvider` returns a failure whose message names the gate (`two_factor_required`). Complete the factor, then sign in again.

The mount path in `basePath` must expose the OAuth plugin routes `/auth/oauth/authorize/:provider` and `/auth/oauth/mobile/exchange`. The OAuth provider's own redirect URI stays your server callback, not the app link.

### Refresh on foreground

Pass React Native's `AppState` as `appState` and the session is re-checked every time the app comes back to the foreground, so a session revoked elsewhere signs the user out.

## Hooks reference

### `useSession`

```tsx
const { session, isLoading, refresh } = useSession();
```

### `useUser`

```tsx
const { user, isLoading, isAuthenticated } = useUser();
```

### `useSignIn`

```tsx
const { signIn, isLoading, error } = useSignIn();
const result = await signIn(email, password);
```

### `useSignUp`

```tsx
const { signUp, isLoading, error } = useSignUp();
const result = await signUp(email, password, name);
```

### `useSignOut`

```tsx
const { signOut } = useSignOut();
await signOut(); // clears stored token and calls server sign-out
```

### `useAgents`

```tsx
const { agents, create, revoke, rotate, isLoading, error } = useAgents(basePath);
```

Manages agent identity records for the current user. Requires the full base URL (same as the provider config).

## `AuthExpoConfig`

| Field | Type | Description |
|---|---|---|
| `basePath` | `string` | Full URL to your theAuth mount point |
| `storage` | `AuthStorage?` | Token persistence adapter. Defaults to in-memory |
| `social` | `SocialSignInConfig?` | Enables `signInWithProvider`. See Social sign-in |
| `appState` | `AppStateLike?` | React Native `AppState`. Refreshes the session on foreground |

<Warning>
The default in-memory storage loses the session when the app restarts. Always pass a real storage adapter in production.
</Warning>
