This is the Go REST client for a theAuth TypeScript server, source in [`sdks/go`](https://github.com/glincker/theauth/tree/main/sdks/go). It talks to the same REST API as `@glinr/theauth-client`. The Go server library is a separate project, [theauth-go](https://github.com/glincker/theauth-go), see its [docs](/go/getting-started/overview).

<Warning>The module path in `sdks/go/go.mod` is `github.com/glincker/theauth-go`, the same path as the server library repository, so `go get` below fetches the server library. Vendor `sdks/go` until the client gets its own path.</Warning>

## Installation

```bash
go get github.com/glincker/theauth-go
```

Requires Go 1.21 or newer. No external dependencies.

## Create a client

```go
client := theauth.NewClient("https://your-app.com/api/theauth",
    theauth.WithToken("ta_..."),
    theauth.WithTimeout(10*time.Second),
)
```

Every method takes a `context.Context` first and returns typed errors.

## Agents and authorization

```go
agent, err := client.Agents.Create(ctx, theauth.CreateAgentInput{
    OwnerID: "user-123",
    Name:    "github-reader",
    Type:    theauth.AgentTypeAutonomous,
})

result, err := client.Authorize(ctx, agent.ID, theauth.AuthorizeRequest{
    Action:   "read",
    Resource: "mcp:github:repos",
})
```

Delegation, audit and human auth live on `client.Delegation`, `client.Audit` and `client.Auth`.

## MCP servers

```go
srv, err := client.MCP.Register(ctx, theauth.RegisterMcpServerInput{
    Name:     "github",
    Endpoint: "https://mcp.example.com",
    Tools:    []string{"read_repo"},
})
servers, err := client.MCP.List(ctx)
found, err := client.MCP.Get(ctx, srv.ID) // nil, nil when missing
```

## Plugin endpoints

Call routes declared with `defineEndpoint` on the Go server. The path below is an example of a route you define yourself, not one the library ships. This client talks to the Go server only: the TypeScript handler serves a different route set (see [REST API](/api)).

```go
var out struct{ ID string `json:"id"` }
err := client.Request(ctx, theauth.RequestOptions{
    Method: "POST",
    Path:   "/auth/team/:teamId/invite",
    Params: map[string]string{"teamId": "t1"},
    Body:   map[string]string{"email": "a@b.c"},
}, &out)
```

`client.Do(ctx, method, path, query, body, &out)` is the short form without path parameters.

## Devices

`client.Devices` is the registry and needs a user or admin token. `client.Device` is what a device calls as itself.

```go
signer, _ := theauth.NewDeviceAssertionSigner("") // the key first, the id after registering
spec, _ := theauth.JWKCredential(signer.PublicJWK())
reg, err := client.Devices.Register(ctx, theauth.RegisterDeviceInput{
    OwnerID:     "user-123",
    Name:        "Pump 4",
    Permissions: []theauth.Permission{{Resource: "mqtt:plant/a/pump4/#", Actions: []string{"publish"}}},
    Credential:  &spec,
})
_ = signer.Bind(reg.Device.ID)

res, err := client.Device.Authorize(ctx, signer, theauth.AuthorizeRequest{
    Action: "publish", Resource: "mqtt:plant/a/pump4/temp",
})
```

The signer makes a new `device-assertion+jwt` for every call, because the server accepts each `jti` once. A `DevicePSK` or `DeviceToken` works as the credential too.

## Step-up and bound tokens

A 401 with `error="insufficient_user_authentication"` (RFC 9470) returns `*theauth.ErrStepUpRequired`. `err.Challenge.AuthorizeParams()` gives the `acr_values` and `max_age` for the new authorization request. `ACRSatisfies` and `AuthIsFresh` check a token before you call.

Set `Cnf: theauth.DPoPConfirmation(prover)` on `CreateAgentInput` to bind an agent token to a DPoP key (RFC 7800). `Agents.Rotate` keeps the binding and `Agents.RotateWith(ctx, id, theauth.RotateOptions{Unbind: true})` removes it. `AuthorizeRequest.Inputs` records what the model had in context for the audit log; the server hashes the content and does not store it.

## Errors

| Check | Meaning |
| --- | --- |
| `theauth.IsNotFound(err)` | 404 |
| `theauth.IsAuthentication(err)` | 401 |
| `theauth.IsPermission(err)` | 403 |
| `theauth.IsCSRFRejected(err)` | 403 with code `CSRF_REJECTED` |
| `theauth.IsRateLimited(err)` | 429, returns `Retry-After` seconds |
| `theauth.ValidationIssues(err)` | `issues` from a plugin endpoint validation failure |

All error types embed `TheAuthError` with `Code`, `Message`, `StatusCode`, `Details` and `Issues`.

## DPoP

Bind tokens to a key with RFC 9449 proofs. The prover uses the standard library only (ECDSA P-256, ES256).

```go
prover, err := theauth.NewDPoPProver()
client.UseDPoP(prover)
```

Each request carries a `DPoP` proof with `htm`, `htu` (no query or fragment), `iat`, `jti` and `ath` when a token is sent. A Bearer token is sent as `Authorization: DPoP <token>`. The `DPoP-Nonce` header is cached per origin and a `use_dpop_nonce` challenge is retried once.

To wrap your own `http.Client`:

```go
hc := theauth.DPoPHTTPClient(http.DefaultClient, prover)
thumbprint := prover.Thumbprint() // jkt
```
