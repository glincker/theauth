## add

Copies theAuth UI components into your project as source you own, in the shadcn style.

```bash
theauth add sign-in
theauth add --list
```

Options: `--dir <path>`, `--overwrite`, `--dry-run`, `--registry <dir|url>`. See [UI components](/ui-components#copy-the-source-into-your-project).

## init

```bash
npx theauth init                          # asks for framework and database
npx theauth init --framework hono --yes   # no prompts
npx theauth init --framework nextjs --db postgres
```

Options:

| Flag | Meaning |
|------|---------|
| `--framework` | `hono`, `express`, `nextjs`, `fastify`, `sveltekit` or `nuxt`. Default: detected from `package.json`, else `hono`. |
| `--db` | `sqlite` (default, a file at `./theauth.db`), `postgres` or `mysql`. |
| `--dir <path>` | Project directory. Default: the current one. |
| `--yes` | Never prompt. Any of `--framework` or `--db` also skips the prompts. |
| `--force` | Replace generated files that already exist. `.env` is never replaced. |
| `--mcp` | Accepted and skipped with a note: it needs the database backed MCP stores, which are not available yet. |

Files it writes, relative to the project directory:

| File | Content |
|------|---------|
| `src/theauth.ts` | The TheAuth instance (created on first use) and the admin key check. |
| `src/seed.ts` | Creates the owner user with `theauth.user.create`, then a `demo-agent`. Safe to run twice. |
| `src/server.ts` | Hono, Express and Fastify: a server that seeds on boot and mounts the adapter at `/api/theauth`. |
| route file | Next.js `app/api/theauth/[...theauth]/route.ts` (under `src/` when it exists), SvelteKit `src/routes/api/theauth/[...path]/+server.ts`, Nuxt `server/api/theauth/[...path].ts`. |
| `.env.example` | Every variable the project reads, with empty secrets. |
| `.env` | Generated 32 byte `THEAUTH_SECRET` and `ADMIN_API_KEY`. Only created when absent, and `.env` is added to `.gitignore`. |

Re-running `init` is safe: files that exist are reported as `skipped` and left alone. It does not edit `package.json`; it prints the install command for the package manager it detected (`npm`, `pnpm`, `yarn` or `bun`). Sample output and the follow-up curl are in the [quickstart](/quickstart#fastest-start-theauth-init). `theauth init --agent` is a different mode that installs the assistant skill and MCP config.

## doctor

```bash
npx theauth doctor
npx theauth doctor --json                                       # for CI
npx theauth doctor --live http://localhost:3000/api/theauth     # also call the running server
npx theauth doctor --fail-on warn                               # exit 1 on warnings too
```

Reads the process environment plus `.env` and `.env.local` in the current directory (the process environment wins), then checks:

| Id | Fails when | Warns when |
|----|-----------|------------|
| `node` | older than 20 | |
| `secret` | `SESSION_SECRET` or `THEAUTH_SECRET` is missing or under 32 characters | looks like a placeholder or has few distinct characters |
| `app-url` | invalid, not https in production, or localhost in production | not set |
| `database` | | not set, or SQLite in production |
| `gitignore` | `.env` is present but not in `.gitignore` | |
| `dependency` | | `@glinr/theauth` not in `package.json` |
| `core-version` | the installed core is outside an installed adapter's peer range | core is not installed yet |
| `schema` | an applied migration was edited (checksum mismatch) | migrations are pending, the SQLite file does not exist yet, or the status could not be read |
| `allow-unauthenticated` | `allowUnauthenticated: true` in source and `NODE_ENV=production` | `allowUnauthenticated: true` in source outside production |
| `trusted-proxy` | | `trustedProxy` is not set in source and `NODE_ENV=production` |

`schema` reads the ledger the same way [`theauth db status`](/database) does, using `DATABASE_URL` or the database in `theauth.config.mjs` when you have one. `allow-unauthenticated` and `trusted-proxy` scan your `src`, `server`, `app`, `lib` and `routes` folders.

### Live mode

`--live [url]` also calls the running server. Give it the URL where you mounted the handler (default `http://localhost:3000/api/theauth`; `--url` is an alias):

| Id | Fails when |
|----|-----------|
| `live-reachable` | the server does not answer, or `GET <url>/agents` answers 404 (nothing mounted there) |
| `live-protected-401` | `GET <url>/agents` without a token answers 2xx (the management routes are open); warns on other non-401 answers |
| `live-mcp-metadata` | a well-known document advertises an endpoint (`authorization_endpoint`, `token_endpoint`, `registration_endpoint`, `revocation_endpoint`, `jwks_uri`) that answers 404 or does not answer |
| `cors.wildcard` | `GET <url>/agents` with an `Origin` header answers `Access-Control-Allow-Origin: *` |
| `headers.security_off_https` (info) | the url is https and the response has no `Strict-Transport-Security` header (a proxy may add it) |

When MCP is not mounted both well-known documents answer 404 and `live-mcp-metadata` passes. Metadata that points at a different origin than the one you probe (a `BASE_URL` of `http://localhost:3001` while the server listens on 3000, for example) fails with the endpoints it could not reach.

### Config rules

When `theauth.config.mjs` or `theauth.config.js` is present, the doctor reads it and checks the settings below. A `.ts` config loads only when the command runs under a TypeScript loader. Each rule has a `severity`: `fail` (exit 1), `warn`, or `info`. A rule appears only when it fires. Messages name settings and counts, never secret values.

| Id | Severity | Fires when |
|----|----------|------------|
| `secret.weak` | fail | `secret`, `auth.session.secret` or `mcp.signingSecret` is under 32 characters, or looks like a default or placeholder |
| `cookie.insecure_http` | fail | `baseUrl` is plain http on a host that is not localhost |
| `webauthn.rpid_mismatch` | fail | `passkey.rpId` is neither the `baseUrl` host nor a parent domain of it |
| `session.ttl_long` | warn | `auth.session.maxAge` is over 30 days |
| `network.trusted_proxies_empty` | warn | `trustForwardedHeaders` is on and `trustedProxy` names no proxy |
| `mfa.none_enabled` | warn | username or session sign-in is configured with neither `totp` nor `passkey` |
| `password.min_length_low` | warn | `username.password.minLength` is under 12 (default 8) |
| `password.pbkdf2_iterations_low` | warn | an iteration override (`username`, `passwordReset`, or `THEAUTH_PBKDF2_ITERATIONS`) resolves below 600000 |
| `saml.tracker_in_memory` | warn | SAML providers are set with neither `sso.storage` nor `secondaryStorage` |
| `mcp.offline_no_jti_denylist` | warn | MCP revocation mode is `offline` (config or `THEAUTH_MCP_REVOCATION_MODE`) and no `mcp.jtiDenylist` is set |
| `cimd.no_host_allowlist` | warn | `mcp.clientIdMetadataDocuments` is enabled with no `allowedHosts` and no `resolver` |
| `mcp.consent_page_missing` | warn | MCP is enabled with no `mcp.consentPage`, so codes are issued without a consent screen |
| `mcp.registration_open` | warn | dynamic client registration is on and `mcp.registration.agentForClient` is not set |
| `hooks.timeout_disabled` | warn | a `beforeAuthorize` or `beforeAgentCreate` hook runs with `timeoutMs` 0 |
| `audit.hmac_key_missing` | warn | `audit.tamperEvident` is on without `audit.hmacKey` |
| `audit.tamper_evident_off` | info | `audit.tamperEvident` is not on, so audit rows are not hash-chained |
| `audit.secrets_table_collision` | warn | `theauth_audit_secrets` in the database (`DATABASE_URL` or the config url) has the layout theauth-go creates (integer `id`, binary `secret`), so both libraries share one database and TheAuth refuses to migrate it |

`audit.secrets_table_collision` is the one rule that reads the database. It runs a dry run of the migrator, which checks the table layout first and writes nothing, and it is left out when there is no database url, the SQLite file does not exist yet, or the database cannot be read (`schema` reports that). Fixes for each id are in the `fix` field of the output.

### Exit code and JSON

Exit code is 1 when any check reaches the `--fail-on` severity, and 0 otherwise. Severities order as `info` < `warn` < `fail`:

| `--fail-on` | Exit 1 when |
|-------------|-------------|
| `fail` (default) | a check failed. Warnings and info findings do not fail the run |
| `warn` | a check warned or failed. Info findings do not fail |
| `info` | any check is not a pass, info findings included |

A check counts as its `severity` when it has one (config rules and some live checks), otherwise as its `status`. A value other than `info`, `warn` or `fail` is a usage error (exit 1, help text printed). With `--json` the `ok` field is false exactly when the exit code would be 1. The default is unchanged, so existing CI that runs `theauth doctor` behaves as before. With `--json` the output is:

```json
{
  "ok": true,
  "checks": [
    { "id": "schema", "status": "pass", "message": "Schema up to date (4 applied)" },
    { "id": "app-url", "status": "warn", "message": "No app URL (THEAUTH_URL or APP_URL)", "fix": "Set it so redirects, cookies and OAuth callbacks use the right origin." }
  ]
}
```

`status` is `pass`, `warn` or `fail`; `fix` appears on non-passing checks. Config rules and the live `cors.wildcard` and `headers.security_off_https` checks also carry `severity` (`info`, `warn` or `fail`). For those, `status` is `fail` when severity is `fail` and `warn` otherwise. The shape is stable: new checks and fields only add entries, so key on `id` and ignore ids and fields you do not know. A check is left out when it does not apply (no `DATABASE_URL`, no adapter in source, no `--live`, no config file, or a rule that did not fire).

## secret

```bash
npx theauth secret                          # 64 hex characters
npx theauth secret --env SESSION_SECRET     # SESSION_SECRET=...
npx theauth secret --bytes 48 --format base64url --count 3
npx theauth secret --json
```

Uses `node:crypto`. Bytes range from 16 to 128.

## completions

```bash
theauth completions bash >> ~/.bashrc
theauth completions zsh > "${fpath[1]}/_theauth"
theauth completions fish > ~/.config/fish/completions/theauth.fish
```
