theauth-go ships a complete OAuth 2.1 Authorization Server (AS) behind `Config.AuthorizationServer`. It is opt-in: callers who do not set this field get the v1.0 surface unchanged.

## Wiring the AS

```go
import "net/netip"

a, _ := theauth.New(theauth.Config{
    Storage:       store,
    BaseURL:       "https://as.example.com",
    EncryptionKey: []byte(os.Getenv("ENCRYPTION_KEY")), // 32-byte AES-256

    AuthorizationServer: &theauth.AuthorizationServerConfig{
        Issuer: "https://as.example.com",
        Resources: []theauth.ProtectedResource{
            {
                Identifier: "https://api.example.com",
                Scopes:     []string{"read", "write"},
            },
        },
    },
})
```

`EncryptionKey` is required when `AuthorizationServer` is set. It protects the Ed25519 signing key at rest.

## Endpoints

Once `AuthorizationServer` is set, `a.Mount(r)` adds the endpoints below. They sit at the root of the router you pass in, not under `/auth` like the sign-in routes. A few things follow from that:

- Call `a.Mount` on your top-level router. If you mount it on a sub-router, every URL below gets that prefix, and the URLs the server advertises in its metadata will not match.
- Set `Issuer` to a bare origin such as `https://as.example.com`. The metadata route is registered only at the root, so an issuer with a path (`https://example.com/tenant1`) will not be discoverable.

To check a running server, fetch `/.well-known/oauth-authorization-server`. It lists the issuer and the full URL of every endpoint your configuration turned on.

### Discovery

Clients and resource servers start here.

| Endpoint | What it returns |
|---|---|
| `GET /.well-known/oauth-authorization-server` | The server's metadata: endpoint URLs, supported grant types, PKCE methods and signing algorithms (RFC 8414). Cached for 5 minutes. |
| `GET /.well-known/oauth-protected-resource` | Metadata for the first entry in `Resources`: which server issues tokens for it and which scopes it accepts (RFC 9728). |
| `GET /.well-known/oauth-protected-resource/{path}` | The same, for a specific resource. `{path}` is the resource's path under your issuer. For a resource with identifier `https://as.example.com/mcp`, request `/.well-known/oauth-protected-resource/mcp`. |
| `GET /oauth/jwks` | The public keys that verify the tokens this server signs (RFC 7517). |

The per-resource route only finds resources that live under the issuer's own host. If your API runs somewhere else, such as `https://api.example.com`, serve its protected resource metadata from that host. The [resource server](/go/concepts/resource-server) package does this for you.

### Getting a token

| Endpoint | Purpose |
|---|---|
| `GET /oauth/authorize` | Starts the authorization code flow. The user must be signed in, so mount your sign-in routes on the same app (RFC 6749, OAuth 2.1). |
| `POST /oauth/token` | Exchanges a code, refresh token or other grant for an access token (RFC 6749, OAuth 2.1). |
| `POST /oauth/revoke` | Revokes a refresh token. The caller must be the client the token was issued to (RFC 7009). |
| `POST /oauth/introspect` | Lets a resource server ask whether a token is still active (RFC 7662). |

### Enabled by configuration

| Endpoint | Turns on when |
|---|---|
| `POST /oauth/register` | The route always exists, but it only accepts requests when you set `RegistrationTokens` or `AllowAnonymousRegistration`. Otherwise it answers `401`. See [Dynamic Client Registration](#dynamic-client-registration) (RFC 7591). |
| `POST /oauth/par` | Pushed authorization requests are enabled and your storage backend supports them. See [PAR and JAR](/go/concepts/par-jar) (RFC 9126). |
| `POST /oauth/bc-authorize` | CIBA is configured and your storage backend supports it. See [CIBA](/go/concepts/ciba). |

## Dynamic Client Registration

```go
AuthorizationServer: &theauth.AuthorizationServerConfig{
    Issuer: "https://as.example.com",

    // Bearer-gated DCR (recommended for production):
    RegistrationTokens:             []string{os.Getenv("DCR_TOKEN")},
    RegistrationRateLimitPerMinute: 5,

    // OR allow anonymous registration (public MCP profile):
    AllowAnonymousRegistration:     true,   // rate-limited to 1 req/min by default
},
```

## Agent identities and delegation

Add `Config.AgentIdentity` to enable agent CRUD and the delegation grant system:

```go
a, _ := theauth.New(theauth.Config{
    // ...
    AuthorizationServer: &theauth.AuthorizationServerConfig{ /* ... */ },
    AgentIdentity: &theauth.AgentConfig{
        MaxChainDepth: 3, // hard ceiling is 3
    },
    AccountUX: true, // expose /account/agents and /account/delegations
})
```

Create an agent:

```go
agent, secret, err := a.CreateAgent(ctx, theauth.CreateAgentInput{
    Owner: theauth.AgentOwner{UserID: &userID}, // or OrganizationID for an org-owned agent
    Name:  "my-mcp-agent",
    Scope: []string{"read", "write"},
})
```

## Trusted proxies

By default, `X-Forwarded-For` is not trusted. Enable it for specific proxy prefixes:

```go
Config{
    TrustedProxies: []netip.Prefix{
        netip.MustParsePrefix("10.0.0.0/8"),
    },
}
```

## Key rotation

Signing keys rotate every 30 days. The JWKS endpoint always serves the current and one previous key so resource servers with a cached JWKS can verify tokens minted before the rotation. Call `a.RotateSigningKey(ctx)` to rotate ahead of schedule.

## Admin surface for agents and delegations

When RBAC is enabled, the admin API gains org-scoped agent and delegation management:

```
GET  /admin/v1/organizations/{orgID}/agents
POST /admin/v1/organizations/{orgID}/agents
GET  /admin/v1/organizations/{orgID}/delegations
POST /admin/v1/organizations/{orgID}/delegations
DELETE /admin/v1/organizations/{orgID}/delegations/{id}
```

These routes require the `agents:admin` and `delegations:admin` RBAC permissions respectively.
