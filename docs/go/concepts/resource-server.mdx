The `mcpresource` module is a zero-dependency Go module for MCP resource servers. It validates bearer JWTs, enforces audience claims, checks RFC 8693 actor chains and delegation grants through AS introspection when a token carries them, and emits the correct `WWW-Authenticate` response on failure.

## Install

```bash
go get github.com/glincker/theauth-go/mcpresource
```

`mcpresource` has **no third-party dependencies**. Importing it does not pull in theauth core or any storage adapter.

## Wire the middleware

```go
package main

import (
    "net/http"

    "github.com/glincker/theauth-go/mcpresource"
    "github.com/go-chi/chi/v5"
)

func main() {
    v := mcpresource.New(
        "https://mcp.example.com",       // the resource URI this server serves
        mcpresource.WithJWKS("https://as.example.com/oauth/jwks"),
        mcpresource.WithIntrospection(
            "https://as.example.com/oauth/introspect",
            "mcp-client-id",
            "mcp-client-secret",
        ),
    )

    r := chi.NewRouter()
    r.Use(v.Middleware)

    r.Get("/tools/run", func(w http.ResponseWriter, r *http.Request) {
        p, _ := v.Principal(r.Context())
        // p.Subject    -- the originating user (or root agent)
        // p.Actor      -- the innermost agent currently acting
        // p.ActorChain -- slice from innermost to outermost
    })

    http.ListenAndServe(":8090", r)
}
```

## What the middleware validates

On every request the middleware:

1. Extracts the bearer token from the `Authorization: Bearer ...` header.
2. Verifies the JWT signature against a cached JWKS (refreshes on `kid` miss and at the configured cache TTL). `EdDSA`, `ES256` and `RS256` are accepted; RSA keys must be at least 2048 bits and the key type must match the header `alg`.
3. Enforces the `aud` claim against the resource URI passed to `mcpresource.New`. `aud` may be a string or an array.
4. Checks `exp`, `nbf`, and `iat` with a 60-second clock skew tolerance (configurable).
5. If a `RevocationChecker` is installed (see below), asks it whether the token was revoked. A revoked token, or a checker error without `WithRevocationFailOpen`, gets a 401.
6. For tokens that carry an `act` claim or a `delegation_grant_id`, calls AS introspection and rejects the request if the AS reports `active: false`, for example because a delegation grant was revoked. Tokens with neither claim are not introspected. Introspection results are cached for the cache TTL, or for the shorter `Cache-Control: max-age` the AS returns.
7. On any failure: emits HTTP 401 with `WWW-Authenticate: Bearer error="invalid_token", resource_metadata="..."` per RFC 6750 and RFC 9728.

## The `Principal` type

```go
type Principal struct {
    Subject    string   // sub claim: user ULID or "agent:<id>"
    Actor      string   // innermost acting identity; equals Subject when no delegation chain
    ActorChain []string // from innermost to outermost
    Scope      []string // scope claim split on spaces
    ClientID   string   // OAuth client that obtained the token
    IssuedAt   time.Time
    ExpiresAt  time.Time
    Audiences  []string  // every aud value the token carried
    ACR        string    // acr claim, empty when absent
    AMR        []string  // amr claim
    AuthTime   time.Time // auth_time claim, zero when absent
    // Issuer, Audience, JWTID, DelegationGrantID, and CnfJKT (DPoP jkt
    // thumbprint) are also populated; see mcpresource/principal.go.
}

// RFC 9396 authorization_details, returned as a copy.
func (p *Principal) AuthorizationDetails() []AuthorizationDetail
```

## Per-tool guards and tool metadata

Mount these after `v.Middleware`:

| API | Purpose |
|---|---|
| `v.RequireScope(scopes...)` | 403 `insufficient_scope` unless the token holds every listed scope (RFC 6750). |
| `v.RequireStepUp(mcpresource.StepUp{ACRValues, MaxAge})` | 401 `insufficient_user_authentication` unless `acr` and `auth_time` satisfy the policy (RFC 9470). `StepUp.Satisfied` runs the same check. |
| `mcpresource.WriteDenial(w, status, d)` | Writes a structured JSON `Denial` body for 401 and 403 responses. |
| `mcpresource.ToolSecurity(scopes...)`, `PublicToolSecurity()` | Build `securitySchemes` metadata for `tools/list`; `Apply` writes it into a tool descriptor. Advisory only. |
| `mcpresource.NewURLElicitation`, `URLElicitationRequiredError` | Build an MCP URL mode elicitation and the `-32042` JSON-RPC error. |

See [Protect MCP tools](/go/guides/protect-mcp-tools) for examples and the limits of each.

## Options

| Option | Default | Description |
|---|---|---|
| `WithJWKS(url)` | none | JWKS endpoint URL for signature verification of JWTs. |
| `WithIntrospection(url, clientID, secret)` | none | Introspection endpoint and client credentials. Used for tokens that carry `act` or `delegation_grant_id`, and for device revocation introspection. The middleware verifies JWTs only; it does not introspect opaque tokens. |
| `WithCacheTTL(d)` | 60s | How long JWKS keys and introspection responses are cached. Values at or below zero are ignored. |
| `WithRevocationChecker(c)` | none | Installs a `RevocationChecker` (`IsRevoked(ctx, token, *Principal) (bool, error)`; `RevocationCheckerFunc` adapts a function). Runs on every authenticated request after offline validation. |
| `WithRevocationFailOpen()` | off | Lets requests through when the checker returns an error. Without it a failing checker denies the request. |
| `WithDeviceRevocationIntrospection()` | off | Checks tokens with a `device_id` claim against the introspection endpoint and passes other tokens. Needs `WithIntrospection`, and replaces any checker set earlier. |
| `WithHTTPClient(c)` | `http.DefaultClient` | Custom HTTP client (e.g., for timeouts or mTLS). |
| `WithClockSkew(d)` | 60s | Tolerance for `exp`/`nbf`/`iat` clock drift. |

## Which options you need

Neither `WithJWKS` nor `WithIntrospection` is required on its own, but with neither set the validator rejects every token and `Validator.Diagnostics()` reports `no-verification-source`. Log the diagnostics at startup.

With `WithJWKS` only, tokens are validated offline (signature, audience, expiry). That path cannot see revocation: a revoked token stays valid until `exp`. Add `WithIntrospection` so `act` and `delegation_grant_id` tokens are checked against the AS, and add `WithRevocationChecker` or `WithDeviceRevocationIntrospection` for tokens revoked before `exp`.

## Concurrent safety

The JWKS and introspection caches use `sync.RWMutex` internally so concurrent reads do not serialize. Cache writes (on miss or TTL expiry) take a write lock for the minimum duration.
