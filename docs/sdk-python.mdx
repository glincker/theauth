The `theauth` package is the Python client for the theAuth REST API. It is built on `httpx` and ships a sync client and an async client with the same surface. Python 3.9 or newer.

## Installation

```bash
pip install theauth
# with DPoP support
pip install "theauth[dpop]"
```

## Create a client

```python
from theauth import TheAuthClient, TheAuthSyncClient

# async
async with TheAuthClient(base_url="https://api.myapp.com/api/theauth", token="ta_...") as client:
    agents = await client.agents.list()

# sync
with TheAuthSyncClient(base_url="https://api.myapp.com/api/theauth", token="ta_...") as client:
    agents = client.agents.list()
```

| Option | Type | Description |
|---|---|---|
| `base_url` | `str` | Mount point of theAuth on your server |
| `token` | `str?` | Bearer token sent on every request |
| `headers` | `dict?` | Extra headers on every request |
| `timeout` | `float` | Request timeout in seconds. Default 30 |
| `auth` | `httpx.Auth?` | Custom auth flow, for example `DPoPAuth` |

## Resources

| Resource | Methods |
|---|---|
| `client.agents` | `create`, `list`, `get`, `update`, `revoke`, `rotate`, `authorize` |
| `client.delegation` | `create`, `list`, `revoke`, `get_effective_permissions` |
| `client.audit` | `query`, `query_paginated`, `export` |
| `client.mcp` | `register`, `list`, `get` |
| `client.auth` | `sign_up`, `sign_in`, `get_session`, `sign_out` |

## MCP servers

```python
from theauth.types import RegisterMcpServerInput

server = await client.mcp.register(
    RegisterMcpServerInput(
        name="github-mcp",
        endpoint="https://mcp.github.com",
        tools=["read_file", "list_repos"],
        rate_limit_rpm=60,
    )
)
found = await client.mcp.get(server.id)  # None when it does not exist
```

## Plugin routes

Call routes declared with `defineEndpoint` through `request()`. It returns the parsed JSON body.

```python
from theauth import ValidationError

try:
    result = await client.request(
        "POST", "/auth/team/invite", json={"email": "a@b.c"}
    )
except ValidationError as err:
    print(err.issues)
```

Validation failures raise `ValidationError` with the server `issues`. A 403 `CSRF_REJECTED` raises `PermissionError`, and a 429 raises `RateLimitError` with `retry_after`.

## DPoP

`DPoPAuth` signs each request with an ES256 key pair, as described in RFC 9449.

```python
from theauth import TheAuthSyncClient
from theauth.dpop import DPoPAuth

auth = DPoPAuth()
jkt = auth.thumbprint()  # bind your access token to this value

with TheAuthSyncClient(base_url=BASE, token=access_token, auth=auth) as client:
    client.agents.list()
```

- The `Authorization` header becomes `DPoP <token>` and the proof carries an `ath` claim.
- `htu` drops the query and fragment.
- The server `DPoP-Nonce` is cached per origin and a `use_dpop_nonce` response is retried once.

<Note>
`DPoPAuth` is a plain `httpx.Auth`, so you can also pass it to your own `httpx.Client` or `httpx.AsyncClient`. The `cryptography` package is imported lazily and a clear error is raised if it is missing.
</Note>

## Devices

`client.devices` is the registry and needs a user or admin token. `client.device` is what a device calls as itself: enroll, authorize, fetch an offline policy bundle.

```python
from theauth import (
    CredentialSpec, DeviceAssertionSigner, RegisterDeviceInput, TheAuthSyncClient,
)
from theauth.types import AuthorizeRequest, Permission

signer = DeviceAssertionSigner()  # the key first, the id after registering
with TheAuthSyncClient(base_url=BASE, token=admin_token) as client:
    reg = client.devices.register(
        RegisterDeviceInput(
            owner_id="user-123",
            name="Pump 4",
            permissions=[Permission("mqtt:plant/a/pump4/#", ["publish"])],
            credential=CredentialSpec.from_jwk(signer.public_jwk),
        )
    )
    signer.bind(reg.device.id)
    result = client.device.authorize(signer, AuthorizeRequest("publish", "mqtt:plant/a/pump4/temp"))
    client.devices.suspend(reg.device.id, "stolen")
```

`DeviceAssertionSigner` signs the `device-assertion+jwt` the server verifies. It makes a new assertion for every call because the server accepts each `jti` once. It needs the `cryptography` extra, like DPoP.

## Step-up

A 401 with `error="insufficient_user_authentication"` (RFC 9470) raises `StepUpRequiredError`, a subclass of `AuthenticationError`. `error.challenge.authorize_params()` gives the `acr_values` and `max_age` for the new authorization request.

```python
from theauth import StepUpRequiredError

try:
    client.approvals.approve(approval_id)
except StepUpRequiredError as err:
    print(err.challenge.authorize_params() if err.challenge else {})
```

`acr_satisfies` and `auth_is_fresh` check a token's `acr` and `auth_time` before you call.

## Bound tokens and input provenance

Pass `cnf=dpop_confirmation(prover)` to `CreateAgentInput` to bind an agent token to a DPoP key (RFC 7800). `client.agents.rotate(id)` keeps the binding, `rotate(id, cnf=None)` removes it. `AuthorizeRequest(inputs=[ProvenanceInput("user_message", content=text)])` records what the model had in context; the server hashes the content and does not store it.

## Errors

All exceptions inherit from `TheAuthError` and carry `code`, `message` and `status_code`.

| Class | When |
|---|---|
| `AuthenticationError` | 401 |
| `StepUpRequiredError` | 401 with a step-up challenge, has `challenge` |
| `PermissionError` | 403 |
| `NotFoundError` | 404 |
| `ValidationError` | 400 or 422 with `issues` |
| `RateLimitError` | 429, has `retry_after` |
| `ServerError` | 5xx |
| `NetworkError` | Transport failure |
