Give your assistant the real docs and API. One command sets it up.

```bash title="terminal"
npx @glinr/theauth-cli init --agent
```

It writes these files in your project root:

| Assistant | Files |
|---|---|
| Claude Code | `.claude/skills/theauth/SKILL.md` and `.mcp.json` |
| Cursor | `.cursor/rules/theauth.mdc` and `.cursor/mcp.json` |
| VS Code | `.vscode/mcp.json` |

`--target claude,cursor,vscode` limits the set (default: all three). `--dry-run` writes nothing. `--force` replaces existing files and `theauth` MCP entries.

Existing files are left alone and other MCP servers stay in place. A config that is not plain JSON (for example, one with comments) is skipped and reported. Add the entry by hand:

```json title=".mcp.json"
{
  "mcpServers": {
    "theauth": { "command": "npx", "args": ["-y", "@glinr/theauth-cli", "mcp"] }
  }
}
```

VS Code uses `servers` with `"type": "stdio"` instead of `mcpServers`.

## Run the theAuth MCP server

`theauth mcp` is a read-only stdio server.

| Tool | What it does |
|---|---|
| `search_docs` | Ranked search over these docs |
| `get_doc` | Full text of one page by slug |
| `add_plugin` | Install command and `plugins` entry. Edits no files. |
| `generate_schema` | SQLite DDL, built in memory. Needs `better-sqlite3`. |
| `inspect` | Setup summary. Env var names, never values. |

## Skill and hosted docs

The skill ([`SKILL.md`](https://github.com/glincker/theauth/blob/main/skills/theauth/SKILL.md)) covers install, plugins, agent identity, delegation and MCP auth. `init --agent` copies it into your project.

The docs site serves a remote MCP server with a search tool over these docs. It needs no install:

```bash title="terminal"
claude mcp add --transport http theauth-docs https://docs.theauth.dev/mcp
```

For Cursor, VS Code, Codex and Gemini CLI, add the same URL as a remote (HTTP) server. Config file names change between releases, so check each tool's MCP docs. The Go docs are not part of this server.

## Rule files

Copy these from [`templates/ai-rules/`](https://github.com/glincker/theauth/tree/main/templates/ai-rules):

| File | Copy to | Tool |
|---|---|---|
| `AGENTS.md` | `AGENTS.md` in your project root | Codex, Cursor, Copilot coding agent, Gemini CLI |
| `.cursor/rules/theauth.mdc` | `.cursor/rules/theauth.mdc` | Cursor |
| `CLAUDE.md` | Append to your `CLAUDE.md` | Claude Code |
| `copilot-instructions.md` | `.github/copilot-instructions.md` | GitHub Copilot |

Gemini CLI reads `GEMINI.md` by default. Copy `AGENTS.md` to `GEMINI.md`, or set `context.fileName` to `AGENTS.md` in `.gemini/settings.json`.

The rules require:

- Never log or commit tokens, secrets or `Authorization` headers.
- Verify delegation with `authorize` or `policy.evaluate`. Never trust a claimed owner.
- Keep policy deny by default. Treat `deny`, `escalate` and errors as do not run.
- Wrap every agent tool with `guardTool` or `guardTools`.
- Use DPoP for MCP tokens that leave your trust boundary.
- Match redirect URIs exactly.

## llms.txt

For assistants that fetch context from URLs:

- [`/llms.txt`](https://docs.theauth.dev/llms.txt): one line per page.
- [`/llms-full.txt`](https://docs.theauth.dev/llms-full.txt): the full text of every page.

Regenerate with `node scripts/generate-llms.mjs`. Add `--check` to fail when they are stale. The Go docs are not included.
