`theAuthAstro(theauth, options?)` returns named route handlers `{ GET, POST, PATCH, DELETE, OPTIONS, ALL }`. Mount them in a catch-all API page so all theAuth paths are handled. Use individual named exports or the `ALL` catch-all handler.

## Install

```bash
pnpm add @glinr/theauth @glinr/theauth-astro
```

## Setup

<Steps>
<Step title="Create the theauth instance">

```typescript
// src/lib/theauth.ts
import { createTheAuth } from '@glinr/theauth';
import { createMcpModule } from '@glinr/theauth/mcp';
import { mcpStore } from './mcp-store'; // storage callbacks, see the MCP page

export const theauth = await createTheAuth({
  database: { provider: 'postgres', url: import.meta.env.DATABASE_URL },
  baseUrl: import.meta.env.AUTH_BASE_URL,
  mcp: { enabled: true }, // creates the MCP tables
});

// baseUrl is the public origin plus the adapter mount path (default /api/theauth)
export const mcp = createMcpModule({
  config: {
    enabled: true,
    issuer: import.meta.env.AUTH_BASE_URL,
    baseUrl: `${import.meta.env.AUTH_BASE_URL}/api/theauth`,
    signingSecret: process.env.MCP_SIGNING_SECRET!, // at least 32 characters
  },
  ...mcpStore,
});
```

</Step>
<Step title="Create the catch-all route">

Create `src/pages/api/theauth/[...path].ts`. The `[...path]` spread catches every sub-path under `/api/theauth/`.

```typescript
// src/pages/api/theauth/[...path].ts
import { theAuthAstro } from '@glinr/theauth-astro';
import { theauth, mcp } from '@/lib/theauth';

// Who may call the management routes. Return { id } to allow, null to reject (401).
// resolveUser needs an auth.adapter; with only auth.session, omit authenticate
// and any valid session is accepted.
const authenticate = async (request: Request) => {
  const user = await theauth.auth.resolveUser(request);
  return user ? { id: user.id } : null;
};

const handlers = theAuthAstro(theauth, { mcp, authenticate });

export const GET = handlers.GET;
export const POST = handlers.POST;
export const PATCH = handlers.PATCH;
export const DELETE = handlers.DELETE;
export const OPTIONS = handlers.OPTIONS;
```

Or use the `ALL` handler to catch every HTTP method in one export:

```typescript
export const ALL = handlers.ALL;
```

</Step>
</Steps>

<Warning>
  Astro requires `output: 'server'` or `output: 'hybrid'` in `astro.config.mjs` to enable API routes. Static output mode does not support server-side route handlers.
</Warning>

## Options

`theAuthAstro(theauth, options?)` takes the same options as the core handler (`createTheAuthHandler` from `@glinr/theauth/http`), so they are identical on every adapter:

| Option | Type | Description |
|--------|------|-------------|
| `mcp` | `McpAuthModule` | Enables the MCP OAuth 2.1 endpoints |
| `basePath` | `string` | URL prefix before the catch-all segment. Defaults to `/api/theauth` |
| `routes` | `{ management?, mcp?, plugins?, explain? }` | Turn route groups off. `mcp` also takes `{ register, authorize, token, revoke, jwks }` booleans |
| `maxBodyBytes` | `number` | Largest request body, default 1 MiB (413 above it) |
| `authenticate`, `allowUnauthenticated`, `trustedProxy`, `rateLimit`, `trustedOrigins`, `csrf` | | Shared security options |

Every route and status code is listed on the [route reference](https://docs.theauth.dev/adapters/routes).

## Protect a route with `requireScope`

```typescript
import { requireScope } from '@glinr/theauth-astro';

export const GET = requireScope(
  theauth,
  { action: 'read', resource: 'invoices' },
  ({ locals }) => Response.json({ agent: locals.agent.id }),
);
```

`requireScope(theauth, { action, resource }, handler)` reads the agent bearer token and checks it may perform the action. It answers 401 (`invalid_token`, `agent_not_found`, `agent_revoked`, `agent_expired`) or 403 (any other denial) with body `{ "error": { "code", "message" } }`, and otherwise passes the agent (without its token) on via `locals.agent`. Pass `clientIp` to feed `ipAllowlist` constraints.

## MCP endpoints

When `mcp` is passed, the MCP OAuth 2.1 endpoints are available at:

```
GET  /api/theauth/.well-known/oauth-authorization-server
GET  /api/theauth/.well-known/oauth-protected-resource
POST /api/theauth/mcp/register
GET  /api/theauth/mcp/authorize
POST /api/theauth/mcp/token
POST /api/theauth/mcp/revoke
GET  /api/theauth/mcp/jwks
```

## Management routes and client IP

With the default session guard, a signed-in user only acts on their own agents, delegations and audit rows. A custom `authenticate` resolver is a trust decision and sees everything.

The adapter does not read forwarded headers for the client IP. Behind a proxy, set `trustedProxy` with `trustedProxyCount` or `trustedHeader`, or `ipAllowlist` constraints cannot match.

```ts
const handlers = theAuthAstro(theauth, { authenticate, trustedProxy: { trustedProxyCount: 1 } });
```

On Cloudflare use `trustedHeader: 'cf-connecting-ip'`. Only trust a header your edge overwrites.
