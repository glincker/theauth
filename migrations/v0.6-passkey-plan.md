# TheAuth v0.6 — Passkey Migration Plan

**Status:** Draft — research only, no code changes
**Date:** 2026-04-29
**Predecessor:** v0.5 session rotation (`@glinr/theauth-react` external mode + `refreshPath`)
**Target:** Move browser-side passkey ceremonies into `@glinr/theauth-react`, mirroring the v0.5 refresh-token pattern.

---

## 1. Goals & non-goals

**Goals**
- Provide first-class React hooks for passkey ceremonies in `@glinr/theauth-react`, parallel to `useSignIn` / `useRotateSession`.
- Keep the consumer's backend authoritative for crypto, storage, and session issuance — theauth React only orchestrates the browser ceremony and POSTs JSON.
- Work with both integration paths: (A) a pre-existing backend (Glinr's Java/Spring impl), and (B) the bundled `kavach-passkey` plugin running as a Node sidecar.
- Replace `@glincker/auth-client/useWebAuthn` (≈511 LOC) with a thinner `@glinr/theauth-react` surface plus consumer-owned UI.

**Non-goals**
- No server-side rewrite of `passkey-plugin.ts` / `passkey.ts` / `cbor.ts`. They already exist in `@glinr/theauth` and stay untouched in v0.6.
- No managed-mode passkey support in v0.6 (deferred). Passkey hooks are external-mode-only, like v0.5 rotation.
- No discoverable-credentials / autofill UI shipped in the package. Conditional-mediation is exposed as a flag; the consumer renders the input.

---

## 2. Hook API

All hooks throw if used outside `<KavachProvider external={…}>`. Each follows the `useSignIn` shape: state machine + single async function returning a discriminated `ActionResult`.

### 2.1 `PasskeyErrorCode`

Mirrors `RotateErrorCode`'s pattern: server-canonical codes + a small set of client categories. Values are derived from the existing `PASSKEY_ERROR` enum in `theauth/packages/core/src/auth/passkey.ts:36`.

```ts
export type PasskeyErrorCode =
  // ── Server (mirror of PASSKEY_ERROR) ─────────────────────────────
  | "challenge_not_found"
  | "challenge_expired"
  | "challenge_replay"
  | "origin_mismatch"
  | "rpid_mismatch"
  | "client_data_type_mismatch"
  | "user_not_present"
  | "user_not_verified"
  | "credential_not_found"
  | "credential_already_exists"
  | "signature_invalid"
  | "sign_count_rollback"
  | "missing_attestation_data"
  | "invalid_attestation"
  | "unsupported_algorithm"
  | "invalid_cose_key"
  | "invalid_client_data"
  // ── Client / browser ─────────────────────────────────────────────
  | "not_supported"          // PublicKeyCredential undefined
  | "user_cancelled"         // NotAllowedError, AbortError
  | "security_error"         // SecurityError (RP ID mismatch, mixed content)
  | "constraint_error"       // ConstraintError (UV not satisfiable)
  | "timeout"                // ceremony timed out
  | "network_error"
  | "server_error"
  | "unauthorized"           // 401 from list/delete (caller not signed in)
  | "unknown";
```

### 2.2 `useRegisterPasskey`

Full registration ceremony in one call: `start → navigator.credentials.create → finish`.

```ts
export interface RegisterPasskeyInput {
  /** Optional friendly device label. Posted to finishRegisterPath. */
  deviceName?: string;
  /** Userhandle override; defaults to the active KavachUser id. */
  userId?: string;
  /** Display name override; defaults to user.name ?? user.email ?? user.id. */
  userName?: string;
}

export type RegisterPasskeyResult =
  | { success: true; credential: PasskeyCredentialSummary }
  | { success: false; code: PasskeyErrorCode; message: string };

export interface PasskeyCredentialSummary {
  id: string;
  credentialId: string;
  deviceName?: string;
  transports?: string[];
  createdAt: string;
  lastUsedAt?: string;
}

export function useRegisterPasskey(): {
  register: (input?: RegisterPasskeyInput) => Promise<RegisterPasskeyResult>;
  status: "idle" | "starting" | "creating" | "finishing" | "error";
  error: { code: PasskeyErrorCode; message: string } | null;
  reset: () => void;
};
```

**Internal flow**
1. POST `apiUrl + passkey.startRegisterPath` (default `/auth/passkey/register/options`) with `{ userId, userName }`.
2. Convert response to `PublicKeyCredentialCreationOptions` (base64url → ArrayBuffer for `challenge`, `user.id`, `excludeCredentials[].id`).
3. `await navigator.credentials.create({ publicKey })`.
4. POST `apiUrl + passkey.finishRegisterPath` (default `/auth/passkey/register/verify`) with `{ userId, deviceName, response: { id, rawId, type, response: { clientDataJSON, attestationObject }, transports } }` (all base64url).
5. On 2xx return success; on error parse `{ error, code }` envelope and map via `mapServerCode`.

### 2.3 `useAuthenticatePasskey`

```ts
export interface AuthenticatePasskeyInput {
  /** Optional userId for non-discoverable flow. Omit for usernameless / autofill. */
  userId?: string;
  /** Use conditional mediation for autofill. Caller is responsible for ensuring
   *  support.conditionalMediationAvailable === true. */
  mediation?: "optional" | "conditional";
  /** Caller-supplied AbortSignal. Required for autofill cancellation. */
  signal?: AbortSignal;
}

export type AuthenticatePasskeyResult =
  | {
      success: true;
      user: KavachUser;
      /** Whatever the consumer's finishAuthPath returns alongside the user. */
      session?: { accessTokenExpiresAt?: Date };
    }
  | { success: false; code: PasskeyErrorCode; message: string };

export function useAuthenticatePasskey(): {
  authenticate: (input?: AuthenticatePasskeyInput) => Promise<AuthenticatePasskeyResult>;
  status: "idle" | "starting" | "asserting" | "finishing" | "error";
  error: { code: PasskeyErrorCode; message: string } | null;
  /** Browser support snapshot (lazy-detected on mount). */
  support: { supported: boolean; platformAuthenticator: boolean; conditionalMediation: boolean } | null;
  reset: () => void;
};
```

**Side effect on success:** the provider runs the same `/me` refresh that `signIn` triggers, so `useUser()` updates synchronously after a successful assertion. This matches v0.5 behavior where `rotateSession()` doesn't change `user` but `signIn()` does.

### 2.4 `useListPasskeys`

```ts
export function useListPasskeys(): {
  passkeys: PasskeyCredentialSummary[];
  isLoading: boolean;
  error: { code: PasskeyErrorCode; message: string } | null;
  refresh: () => Promise<void>;
};
```

Auto-loads when `user` becomes non-null. GETs `apiUrl + passkey.listPath` (default `/auth/passkey/credentials`) with `credentials: "include"`. Returns the JSON envelope `{ credentials: PasskeyCredentialSummary[] }`.

### 2.5 `useDeletePasskey`

```ts
export type DeletePasskeyResult =
  | { success: true }
  | { success: false; code: PasskeyErrorCode; message: string };

export function useDeletePasskey(): {
  remove: (credentialId: string) => Promise<DeletePasskeyResult>;
  status: "idle" | "removing" | "error";
  error: { code: PasskeyErrorCode; message: string } | null;
};
```

DELETEs `apiUrl + passkey.deletePath` with `:id` substitution (default template `/auth/passkey/credentials/:id`).

### 2.6 Error code map override

Same hook as v0.5 — consumers with bespoke server codes pass `passkey.errorCodeMap`:

```ts
errorCodeMap: { CHALLENGE_NOT_FOUND: "challenge_not_found", BAD_RPID: "rpid_mismatch" }
```

## 3. `ExternalAuthConfig` additions

Append a single optional `passkey` block. When omitted, the four hooks throw `not_configured` on first use.

```ts
export interface ExternalAuthConfig {
  // … existing fields (apiUrl, mePath, refreshPath, retry, onAuthError, etc.)

  /**
   * Passkey integration (v0.6+). Set to enable useRegisterPasskey,
   * useAuthenticatePasskey, useListPasskeys, useDeletePasskey.
   */
  passkey?: PasskeyEndpointConfig;
}

export interface PasskeyEndpointConfig {
  /** POST. Body: { userId, userName }. Returns PublicKeyCredentialCreationOptions
   *  with base64url-encoded buffers. Default: "/auth/passkey/register/options". */
  startRegisterPath?: string;

  /** POST. Body: { userId, deviceName?, response }. Returns
   *  { credential: PasskeyCredentialSummary }. Default: "/auth/passkey/register/verify". */
  finishRegisterPath?: string;

  /** POST. Body: { userId? }. Returns PublicKeyCredentialRequestOptions.
   *  Default: "/auth/passkey/authenticate/options". */
  startAuthPath?: string;

  /** POST. Body: { response }. Returns { user, session?: { accessTokenExpiresAt }, credential? }
   *  and sets the session cookie. Default: "/auth/passkey/authenticate/verify". */
  finishAuthPath?: string;

  /** GET. Returns { credentials: PasskeyCredentialSummary[] }.
   *  Default: "/auth/passkey/credentials". */
  listPath?: string;

  /** DELETE. ":id" is replaced with the credentialId.
   *  Default: "/auth/passkey/credentials/:id". */
  deletePath?: string;

  /** Map bespoke server codes to canonical PasskeyErrorCode. */
  errorCodeMap?: Partial<Record<string, PasskeyErrorCode>>;

  /** Forwarded to startAuthPath; lets the server scope challenge userVerification. */
  userVerification?: "required" | "preferred" | "discouraged";

  /** Per-ceremony timeout in ms. Defaults to 60_000 (matches theauth core). */
  timeoutMs?: number;
}
```

**Defaults rationale:** the paths match `theauth/packages/core/src/auth/passkey-plugin.ts:38-257` exactly so a consumer running the bundled plugin gets zero-config integration.

## 4. Backend contract

### 4.1 Request / response shapes

All buffers are **base64url** (no padding). This is what the existing `core/src/auth/passkey.ts` already emits and consumes.

#### `POST /auth/passkey/register/options` (start register)

Request:
```json
{ "userId": "u_abc123", "userName": "ada@example.com" }
```

Response (200):
```json
{
  "challenge": "p7Jk3V…",
  "rp": { "name": "Glinr", "id": "glincker.com" },
  "user": { "id": "u_abc123", "name": "ada@example.com", "displayName": "ada@example.com" },
  "pubKeyCredParams": [
    { "type": "public-key", "alg": -7 },
    { "type": "public-key", "alg": -257 },
    { "type": "public-key", "alg": -8 }
  ],
  "timeout": 60000,
  "attestation": "none",
  "authenticatorSelection": {
    "userVerification": "preferred",
    "residentKey": "preferred",
    "requireResidentKey": false
  },
  "excludeCredentials": [
    { "id": "AAEC…", "type": "public-key", "transports": ["internal"] }
  ]
}
```

Hook converts: `challenge`, `user.id`, `excludeCredentials[].id` → `Uint8Array.from(fromBase64Url(…))` before calling `navigator.credentials.create({ publicKey })`.

#### `POST /auth/passkey/register/verify` (finish register)

Request:
```json
{
  "userId": "u_abc123",
  "deviceName": "MacBook Pro Touch ID",
  "response": {
    "id": "AAEC…",
    "rawId": "AAEC…",
    "type": "public-key",
    "transports": ["internal", "hybrid"],
    "response": {
      "clientDataJSON": "eyJ0eXBlIjo…",
      "attestationObject": "o2NmbXR…"
    }
  }
}
```

Response (200): `{ "credential": PasskeyCredentialSummary }`
Response (4xx): `{ "error": "Challenge expired", "code": "CHALLENGE_EXPIRED" }`

#### `POST /auth/passkey/authenticate/options` (start auth)

Request: `{ "userId": "u_abc123" }` (or `{}` for usernameless flow)
Response (200):
```json
{
  "challenge": "wXY…",
  "rpId": "glincker.com",
  "timeout": 60000,
  "userVerification": "preferred",
  "allowCredentials": [
    { "id": "AAEC…", "type": "public-key", "transports": ["internal"] }
  ]
}
```

#### `POST /auth/passkey/authenticate/verify` (finish auth)

Request:
```json
{
  "response": {
    "id": "AAEC…",
    "rawId": "AAEC…",
    "type": "public-key",
    "response": {
      "clientDataJSON": "eyJ0…",
      "authenticatorData": "Lq…",
      "signature": "MEU…",
      "userHandle": "dV9hYmM…"
    }
  }
}
```

Response (200) — must set the session cookie (existing plugin already does this at `passkey-plugin.ts:159-183`):
```json
{
  "user": { "id": "u_abc123", "email": "ada@example.com" },
  "session": { "token": "…", "expiresAt": "2026-04-28T…", "accessTokenExpiresAt": "2026-04-28T…" },
  "credential": { "id": "…", "credentialId": "…", "counter": 7 }
}
```

The hook reads `accessTokenExpiresAt` (if present) and pipes it through `onSessionRotated` so the proactive rotation timer learns the new expiry — clean handoff with v0.5.

#### `GET /auth/passkey/credentials` (list)

Response: `{ "credentials": [{ id, credentialId, deviceName, transports, createdAt, lastUsedAt }] }`. Already implemented at `passkey-plugin.ts:198-221`.

#### `DELETE /auth/passkey/credentials/:id`

Response: `{ "removed": true }` or `{ "error": "...", "code": "CREDENTIAL_NOT_FOUND" }`.

### 4.2 Spec references

- WebAuthn L2 §5.1 (registration ceremony) — `clientDataJSON.type === "webauthn.create"`, attestation object CBOR layout.
- WebAuthn L2 §5.2 (authentication ceremony) — `clientDataJSON.type === "webauthn.get"`, signed data is `authenticatorData ‖ SHA-256(clientDataJSON)`.
- §13 (RP ID): must be a registrable suffix of the document origin. TheAuth core enforces this via `rpIdHash` comparison at `passkey.ts:697-703` and `:904-910`.
- §6.3.2 (UV flag): plugin already enforces via `FLAG_UV` at `passkey.ts:711-716`.

## 5. Two integration paths

### Path A — Consumer-owned backend (Glinr today)

**Topology:** theauth React → Next.js proxy (httpOnly cookie attach) → Java Spring (`/api/v1/webauthn/*`).

**What changes for Glinr:** replace `@glincker/auth-client/useWebAuthn` with `@glinr/theauth-react` hooks. The Next.js proxy at `apps/app-core/src/app/api/webauthn/[...path]/route.ts:36-115` stays — the theauth hooks call `/api/webauthn/*` paths via `external.apiUrl` set to the Next.js origin. Java endpoints stay; we just remap `passkey.startRegisterPath` etc. to match the Java route names:

```ts
external: {
  apiUrl: "",                                              // same-origin
  passkey: {
    startRegisterPath: "/api/webauthn/register/start",
    finishRegisterPath: "/api/webauthn/register/finish",
    startAuthPath: "/api/webauthn/authenticate/start",
    finishAuthPath: "/api/webauthn/authenticate/finish",
    listPath: "/api/webauthn/credentials",
    deletePath: "/api/webauthn/credentials/:id",
    errorCodeMap: {
      WEBAUTHN_CHALLENGE_EXPIRED: "challenge_expired",
      WEBAUTHN_INVALID_SIG: "signature_invalid",
      // … fill in based on Spring's enum
    },
  },
},
```

Backend changes required: ensure response envelopes match (Java may need a small adapter to rename fields, e.g. `credentialId` casing, base64url vs base64). One-time work, tracked as a sibling ticket.

### Path B — Node sidecar runs `kavach-passkey` plugin

**Topology:** Browser → React app (theauth hooks) → Node sidecar (`@glinr/theauth` with `passkey()` plugin mounted) → shared Postgres.

The sidecar exposes the default `/auth/passkey/*` paths. Consumers point `external.apiUrl` at the sidecar (or front it with their gateway) and leave `passkey.*Path` at defaults. Cookies must be on a shared parent domain so the consumer's main app sees the session.

For consumers without a JS runtime in the main backend, this is the wholesale path. For Glinr, this is theoretical — Glinr already has Path A working.

## 7. Open questions & risks

### 7.1 Conditional UI / autofill mediation

- WebAuthn supports `mediation: "conditional"` for autofill on `<input autocomplete="username webauthn">`. Today Glinr's `useWebAuthn` does not expose this.
- **Plan:** `useAuthenticatePasskey` accepts `mediation` + `signal`. Detection lives in `support.conditionalMediation` (`PublicKeyCredential.isConditionalMediationAvailable()`).
- **Risk:** Safari < 17 and Firefox have inconsistent support. Document the support matrix in README.

### 7.2 RP ID strategy

| Env | Hostname | RP ID | Origin |
|---|---|---|---|
| Local dev | `localhost` | `localhost` | `http://localhost:3000` |
| Staging | `auth-staging.glincker.com` | `glincker.com` | `https://auth-staging.glincker.com` |
| Prod | `auth.glincker.com`, `app.glincker.com` | `glincker.com` | `https://auth.glincker.com`, `https://app.glincker.com` |

The RP ID is server-controlled (returned by `start*` endpoints, validated by `verify*`). `glinr-frontend/packages/auth-client/src/client/WebAuthnClient.ts:53-75` derives RP ID client-side today — this is **redundant** because the server's `getRegistrationOptions` already returns it. The theauth hooks should not duplicate that logic; the browser uses whatever the server sent.

**Open question:** does the Java backend already return the correct parent-domain RP ID? If not, that's a one-line Spring config change to add.

### 7.3 Browser support matrix

- `navigator.credentials.create/get` — Chrome ≥ 67, Firefox ≥ 60, Safari ≥ 13.
- Conditional UI — Chrome ≥ 108, Safari ≥ 16, Firefox WIP.
- `Ed25519` (COSE alg -8) — Chrome ≥ 113, Safari TBD; falls back to ES256/RS256 which all platforms support.
- Hybrid transport (cross-device QR) — Chrome ≥ 108, Safari ≥ 16.

`useAuthenticatePasskey().support` exposes `{ supported, platformAuthenticator, conditionalMediation }` so consumers can render fallbacks.

### 7.4 Browser error → `PasskeyErrorCode` map

| DOMException | `PasskeyErrorCode` | Cause |
|---|---|---|
| `NotAllowedError` | `user_cancelled` | User dismissed the prompt or timeout fired |
| `AbortError` | `user_cancelled` | Caller aborted via `signal` |
| `SecurityError` | `security_error` | RP ID not registrable suffix; mixed content |
| `ConstraintError` | `constraint_error` | UV required but authenticator can't satisfy |
| `InvalidStateError` (register) | `credential_already_exists` | Authenticator already has this credential |
| `NotSupportedError` | `not_supported` | Browser doesn't support the algorithm set |
| `TimeoutError` (rare) | `timeout` | Some browsers throw this instead of NotAllowedError |
| `TypeError` (fetch) | `network_error` | DNS / CORS / offline |
| AbortController timeout | `timeout` | Hook-side timeout exceeded `passkey.timeoutMs` |

### 7.5 Misc

- **Cookie scoping for cross-subdomain:** session cookie must be `Domain=glincker.com` for `app.glincker.com` to see a passkey login from `auth.glincker.com`. Already handled by `buildSetCookie` in `theauth/packages/core/src/plugin/helpers.ts` — verify Java's cookie scoping matches.
- **CSRF for `finishAuth`:** the verify endpoints today rely on the challenge being one-time-use (`passkey.ts:673,882`). Path A's Next.js proxy adds the `Authorization` header — that's belt-and-braces but not a security primitive for the assertion itself.
- **Multi-tenant rpId:** if TheAuth ever ships a multi-tenant SaaS, RP ID needs to be tenant-scoped; out of scope for v0.6.
- **ManagedProvider parity:** `useRegisterPasskey` in managed mode currently throws. Future v0.7 work could make it call the bundled plugin's `/auth/passkey/*` paths against `basePath`.

## Summary

Decision: ship `@glinr/theauth-react@0.6.0` with four passkey hooks (`useRegisterPasskey`, `useAuthenticatePasskey`, `useListPasskeys`, `useDeletePasskey`) that mirror v0.5's external-mode pattern — client orchestrates the WebAuthn ceremony, consumer's backend owns crypto and storage. Adds a `passkey` block to `ExternalAuthConfig` with sensible defaults matching the existing `kavach-passkey` plugin paths. Glinr migrates by swapping 5 call sites and deleting ~1,550 LOC from `@glincker/auth-client`. Estimated 7 engineer-days. Before approving the PR, review: (1) the `PasskeyErrorCode` enum vs Java's existing error names, (2) RP ID strategy across `*.glincker.com`, (3) whether to retire the Next.js WebAuthn proxy or keep it for httpOnly cookie attach.
